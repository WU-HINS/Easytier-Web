## 1. F-215（P2）compose 把驱动写死，切 PostgreSQL 静默失效

文件头注释写着"导出 `EASYTIER_DB_DRIVER=postgres` 再 `--profile postgres`"，
而 `environment:` 里是字面量 `sqlite` 与 `/data/et.db`——**不插值，宿主机环境永远覆盖不了**。
按文档操作的结果是：db 容器起来了，控制台还在用 SQLite，而且不报错。

修法三件：

| 改动 | 原因 |
|---|---|
| 驱动与 DSN 改为 `${VAR:-默认值}` 插值 | 宿主机环境才真的能覆盖 |
| 补 `depends_on`（`required: false`） | profile 启用时等 db 健康；未启用时不影响 |
| 头部注释改成可直接复制的三段式 | 原来三条命令被挤在一行，复制即坏 |

并加规则：`check-readme` 现在会检查 compose 里这两项必须是插值。自测把驱动改回字面量：

    docker-compose.yml:22 hardcodes EASYTIER_DB_DRIVER; interpolate it or the documented switch is a no-op

坦白一句：这个环境没有 docker，我**没能**真的跑 `docker compose --profile postgres up`。
能证明的是"文件层面不再写死、且有规则守着"，不能证明"容器里切换成功"。这条我按"证据够到哪算哪"记 FIXED，
并在台账里写明了这个边界。

## 2. F-220（P2）绑定已被占用的身份返回 500

两个人把同一个 IdP 身份绑到各自账号时，第二次撞 `uq_users_oidc_identity`，
handler 只看到"一个错误"，于是回 500。语义上这是冲突（409）。

修法：bal 新增 `ErrOIDCIdentityTaken`，把唯一冲突映射过去；handler 遇它返回 409。

探针（去掉映射）暴露出来的正是原先把人逼成"服务器错误"的那段驱动文本：

    second bind = bal: bind oidc: constraint failed: UNIQUE constraint failed: users.oidc_issuer, users.oidc_subject (2067)
