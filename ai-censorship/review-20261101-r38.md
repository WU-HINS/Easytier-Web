# 第 38 轮评审（2026-11-01）— 撤销要真的撤销

r37 登记了 F-086：**移除成员不等于撤销访问**。本轮把它做掉。

## 1. 问题复述

移除成员后我们只是"不再推送"，设备侧实例继续运行、继续和网络内其他节点连通。
上游 `runtime_revision.rs` 会调 `delete_network_instance`。我们的撤销是假的。

## 2. 修法：按设备比对期望实例集合

`Reconciler` 新增 `Instances`（`manager` 实现 `OnlineInstances`），每轮对账后：

1. 由所有网络的成员关系算出 `expected[device]`（期望运行的实例 id）；
2. 由所有网络 × 设备算出 `managed[device]`（控制台**可能**创建过的 id 集合，
   因为 `InstanceID(network, device)` 是确定的，即使成员关系已删也能算出来）；
3. 对比设备上报：若"多出来的实例"全部落在 `managed` 里 → 下发
   `RetainNetworkInstance(期望 ∩ 上报)`；
4. 若混入任何**控制台不知道**的实例 → **整体跳过**，只记一条日志。

第 4 条是关键的安全阀：设备可能用本地 TOML 跑着别的网络，控制台无权停它。
宁可漏收一个孤儿，也不能误杀用户的本地实例。

## 3. 两个方向的用例

| 用例 | 场景 | 断言 |
|---|---|---|
| `TestOrphanInstanceIsStopped` | 设备在两个网络，移除其中一个成员关系 | 下发 Retain，内容**只保留存活网络**的实例；`report.Stopped == 1` |
| `TestForeignInstanceIsLeftAlone` | 设备多跑一个本地实例 | **一次 Retain 都不发**，`Stopped == 0` |

第二条用例是这条修复的安全边界，没有它这次改动就是危险的。

## 4. 过程中的一个自纠

第一版测试断言写成了"Retain 里应当包含被删掉的实例"——方向搞反了（Retain 是**保留列表**）。
测试失败后先怀疑实现，核对 `RetainNetworkInstanceRequest{InstIds}` 语义才确认是断言错。
同时发现 `keep` 列表有重复项（期望集合来自多次遍历），顺手加了去重。

## 5. 已知取舍（写清楚）

- 设备同时有"控制台孤儿 + 本地实例"时，本轮**不动手**。要支持这种情况，需要在协议里区分实例来源，
  当前心跳只上报 id，无法判定归属。
- 本轮只处理"成员被移除"；"整个网络被删除"走同一条路径（网络不在 `networks` 列表里 →
  其实例必然落到 `managed` 却不在 `expected`），行为一致但未单独写用例。
