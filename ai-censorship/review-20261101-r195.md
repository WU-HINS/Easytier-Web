# 第 195 轮评审（2026-11-01）— 实例接收限速落地（先确认协议里有这个字段）

目标里"(B) 实例接收限速"这一项，先要回答一个问题：**我们的配置协议里到底有没有这个字段**。

## 1. 先查，再写

起初 grep 我们的 pb 只找到 mtu，没有 rate；差点得出"无法实现"的结论。
再查上游 core_config.proto，发现 TrafficConfig 里有 instance_recv_bps_limit；
回头在我们的 manage.pb.go 里精确搜索，字段其实在：

    InstanceRecvBpsLimit *uint64  (proto field 60, json instance_recv_bps_limit)

**结论：能力在协议里，只是 intent 层从来没 Anyone 用过。**

## 2. 改动

| 层 | 改动 |
|---|---|
| intent | Overrides 增加 instance_recv_bps_limit（uint64） |
| 合并 | MergeOverrides 逐字段，成员优先 |
| 编译 | Compile 写入 cfg.InstanceRecvBpsLimit |

## 3. 证据

用例扩展后同时断言：继承成员拿到网络值 1000000，覆盖成员拿到自己的 250000。
探针删掉编译期写入：inheriting member rate limit = 0, want the network value 1000000。

## 4. 判断

这一轮真正的产出不是代码，而是**把"做不到"这个结论推翻**：
第一次 grep 没找到，并不等于不存在——它只是在别的 pb 文件、别的命名下。
