# 第 239 轮评审（2026-11-01）— 实例详情：把设备自己看到的东西显示出来

原版 NetworkDetail 里的"节点抽屉"是它最实用的一块：点开一个节点，能看到连接类型、远端地址、延迟、丢包、流量、路由表。
我们之前只有成员列表里的一行「10.180.0.1」。

## 1. 关键发现：不用新接口

CollectNetworkInfo 早就把 peers / routes 带回来了（PeerConnInfo 里有 tunnel、stats、loss_rate）。
所以这一轮**没加后端代码**，只是把已有数据渲染出来——和 TOML 那轮是同一类问题：数据在，界面没接。

## 2. 面板内容

| 区块 | 列 |
|---|---|
| 对端 | 对端 ID / 连接类型 / 远端地址 / 延迟 / 丢包 / ↓↑ 流量 |
| 路由 | 对端 ID / 主机名 / 开销 / 下一跳 |

5 秒轮询，与概览页的节奏一致。

## 3. 一个 UX 判断

第一版我把「实例」按钮限制在 running 的成员上，结果演示环境里设备掉线后**根本点不开**——
而设备掉线恰恰是最需要看它报告了什么的时候。改成只要存在 instance_id 就能打开，错误状态保留标题。

## 4. 过程中的自伤

插入 JSX 时把 Button 插到了另一个属性的中间，把文件搞坏；修的时候又用负数下标误改了隔壁的 ACL 按钮守卫。
两次都是 tsc 立刻报错兜住的。教训：**改 JSX 用行号定位要先用断言校验那一行内容**，我这次加了 assert 才没继续错下去。

## 5. 验证

浏览器实测：面板出现「实例详情 / 对端 / 路由」，0 console error；ui tour 增至 **26 条断言**，新增一条。
