# 第 123 轮评审（2026-11-01）— 键盘用户要按十几次 Tab

R-A 第三轮：错误提示能被听见之后，看"能不能高效地走到正文"。

## 1. F-195（P2）没有跳过导航的入口

侧边栏有 8 个导航项，位于每页最前面。键盘用户每换一页，都要先 Tab 过这 8 项才能碰到正文；
在设置页这种长表单里，这个成本是**每次导航都要付一遍**。

WCAG 2.4.1（绕过区块）要求提供跳过重复内容的机制。

## 2. 修法

    <a href="#main-content" className="sr-only focus:not-sr-only focus:absolute ...">
      {copy.shell.skipToContent}
    </a>
    ...
    <main id="main-content" tabIndex={-1}>

平时视觉隐藏，按 Tab 时出现在左上角。`tabIndex={-1}` 让焦点真的能落到 main 上（否则只滚动不聚焦，读屏不会切换上下文）。

check-ui 增加规则：必须存在 `href="#main-content"`，且 `<main>` 必须带同一个 id。
自测把链接目标改成 `#content` 后立即报 "has no skip link to #main-content"。

## 3. 顺手确认的两件事

| 检查 | 结论 |
|---|---|
| 当前页有没有 `aria-current` | react-router 6.26 的 NavLink 会自动加 `aria-current="page"`（在打包产物里确认到 3 处实现），无需手写 |
| 有没有 `<main>` 地标 | 有，本轮补上 id 与 tabIndex |

第一条是先怀疑、后验证的：我原本打算手写 aria-current，查了依赖实现才确认是多余的。

## 4. 台账

195 项：185 FIXED / 7 ACCEPTED / 3 MONITOR / 0 OPEN。

## 5. 判断

可访问性里最容易漏的是"效率"这一类：功能都能用，但某类用户要花十倍力气。
对比度、标签、live region 之后，跳过链接属于同一族——**让不同的人用同样的力气完成同一件事**。
