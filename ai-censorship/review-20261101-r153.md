# 第 153 轮评审（2026-11-01）— 把最后一条 OPEN 关掉：扫描器看不见的东西

F-243 是红队第三轮留下的最后一条：check-contract 的两条新防线都有盲区。

## 1. 盲区一：注释里的"调用"也算调用

扫描器读的是源码原文。于是在客户端里注释掉一行 request 调用，
就能让"每条路由都要有客户端调用"这条断言静音——
注释不参与编译、不参与执行，但参与正则。

修法：扫描前先丢掉整行注释（以双斜杠、块注释开头、或星号开头的行）。
不是完整的词法分析，但恰好覆盖了"注释掉一行来骗过扫描"这种最小手法。

## 2. 盲区二：导航只认两种写法

原来只识别 new URL(字符串) 与 href=双引号字面量。而真实代码里还有：

| 写法 | 原来 | 现在 |
|---|---|---|
| window.location.assign(字符串) | 漏 | 识别 |
| href={ 字符串 }（JSX 表达式） | 漏 | 识别 |
| 模板字符串形式 | 漏 | 识别 |

修法：把"导航"的判断换成**任何引号内含 /api/v1/ 的字符串**。
这会把 request 的路径也重复登记一次——无害，因为 used 集合按方法+路径去重；
换来的是三种写法全部纳入。

## 3. 两个探针

| 攻击 | 现在的结果 |
|---|---|
| 死路由 + 注释掉的假调用 | contract: 1 route(s) no client reaches and no reason is recorded |
| assign 到不存在的路由 | contract: 1 client call(s) without a server route |

两条都从"静音"变成"变红"，而且指名道姓。
