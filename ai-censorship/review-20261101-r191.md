# 第 191 轮评审（2026-11-01）— 把边界写回章程

上一轮我说"这条应该写进 root.md 的边界表，而不是留在对话里"，然后没写。这轮补上。

## 1. 边界表的变化

原来只有一行含糊的"UDP 乱序/重复：部分已测，跨 NAT 与乱序未实测"。
现在拆成三行，各自标明证据或缺失原因：

| 条目 | 状态 |
|---|---|
| UDP 乱序 | 已测（TestReorderedPiecesOverUDPStillMerge） |
| UDP 源端口重绑定 | 已测（TestUDPPeerThatChangesSourcePortGetsANewTunnel） |
| 跨公网 NAT 的地址映射与穿透 | 未实测：需要第二台机器与一个真实 NAT |

## 2. 为什么值得单独当成一轮

一行含糊的边界会让人以为"整个 UDP 场景都没测"，于是要么过度担心，要么干脆跳过；
三行精确的边界让人知道**哪一半测过了、哪一半真的做不了**。

章程里的一句话，比记录里的十句话更有用——因为章程会被反复读到。
