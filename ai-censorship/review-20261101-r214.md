# 第 214 轮评审（2026-11-01）— 数据面卡在 /dev/net/tun，不是卡在代码

目标要求"用 port-forward 打一条真实 TCP 通路"。这一轮把能做的都做了，结论是：**这个沙箱做不到**。

## 1. 证据链

| 尝试 | 结果 |
|---|---|
| port-forward 绑定本端虚拟 IP | EADDRNOTAVAIL（os error 99） |
| 成员级 proxy_cidrs 暴露 127.0.0.2/32 | **路由层接受**：对端 route 表出现 proxy_cidrs=127.0.0.2、经中继 |
| 从另一端 forward 到 127.0.0.2:9001 | 超时（curl exit=28），本机服务未被访问到 |
| 对照：直连 127.0.0.2:9001 | overlay-ok（服务本身没问题） |

根因：no-tun 模式下虚拟 IP 不落在本机网卡上，EasyTier 的"虚拟 IP 监听"和子网代理都要把包**注入本机协议栈**，
这需要 tun 设备（或对应权限）。

## 2. 固化成脚本

新增 scripts/overlay-smoke.sh，三步：

1. 两台实例 running（实测通过）；
2. 对端出现 peer 表（实测通过）；
3. 数据面 —— 缺 /dev/net/tun 时**退出码 3**，明确表示"未验证"。

这沿用之前定下的规矩：未验证 ≠ 通过，用不同的退出码区分。

## 3. 判断

这一轮没有新功能，价值在于把"还没验证"变成"一条别人能跑的命令"。
在带 tun 的机器上跑 scripts/overlay-smoke.sh，第 3 步就是终局证据。
