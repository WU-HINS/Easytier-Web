# 第 84 轮评审（2026-11-01）— 心跳的边界规则

继续"只存在于代码里的规则"。这次是两个心跳参数。

## 1. F-147（P2）三条边界只活在 if 里

`Policy.Validate` 规定：

| 规则 | 现在的样子 |
|---|---|
| 间隔 | 1s .. 60s |
| 超时 | 5s .. 120s |
| 关系 | 超时必须比间隔大 5s |

没有用例。而这三种检查的**错误几乎总发生在边界上**：写成 `<` 还是 `<=`、写 `+5s` 还是 `+4s`。
写错的后果很具体——拒绝一个合理配置，或者让设备因为"晚一秒"被判定掉线。

新用例 10 组值，**把两端和刚好等于边界都跑一遍**：

    1s / 60s / timeout = interval+5s      -> 通过
    500ms / 61s / 4s / 121s / +4s / <interval -> 拒绝

另有一条确认校验接在 `NewManager` 上：坏配置在**启动**就失败，而不是等第一次心跳。

## 2. 手工验证暴露了 F-148

用守护进程试了两种坏配置，两条都正确退出：

    easytier-webd: session: heartbeat interval must be within 1s..60s
    easytier-webd: session: heartbeat timeout must exceed the interval by 5s

但输出里还有一行**不该出现**的东西：

    WARNING: not initialized and no setup token; anyone who can reach this port can claim the admin account

这是因为 r76 加的初始化风险提示被放在配置校验**之前**——一个必然启动失败的进程，先发了一条安全告警。
告警本身没错，但它在"服务根本没起来"的场景里是**误导**：运维会去查网络暴露，而真正的问题是参数。

修法：把提示移到会话管理器构造成功之后。现在坏参数启动只输出错误本身。
