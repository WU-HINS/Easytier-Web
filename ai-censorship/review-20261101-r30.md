# 第 30 轮评审（2026-11-01）— 金样测试当场抓到一个越权漏洞

r29 的结论是"把 `Compile` 输出做成金样测试"。做完之后，**金样自己立刻暴露了两个问题**。

## 1. F-071 金样测试（手段）

7 个场景：`standalone-plain`、`standalone-secure`、`manual-with-peers`、
`acl-policy`、`member-override`、`hostname-override`、`temporary-credential`。
每个场景把编译结果渲染成 prototext 存进 `testdata/golden/*.txt`，`UPDATE_GOLDEN=1` 更新。
连跑 3 次确认确定性。

## 2. F-069（P1）ACL 规则被放宽成"允许任意来源"

写完金样第一件事是**逐条读生成物**。读到 `acl-policy.txt` 时发现：

```
acl:  { acl_v1: { chains: {
  name: "console-inbound"  chain_type: Inbound  enabled: true
  rules: { priority: 65535  enabled: true  protocol: Any  action: Allow }
  default_action: Drop
} } }
```

策略写的是"默认拒绝，只允许 10.42.0.0/29"，但生成物里那条 Allow 规则**没有任何来源约束**——
等于"默认拒绝 + 允许所有"。**这是 fail-open**：越想收紧的配置，实际越宽松。

根因：`selectorCIDRs` 只认 `all/member/subnet`，其它类型直接 `switch` 落空、静默跳过。
我第一次写场景时用了 `type: cidr`（不在词表里），于是约束被丢弃，规则变宽。

**修复**：未知类型、非法 CIDR、引用不存在的成员——全部返回错误，编译失败。
配合 r20 的"写入即校验"，用户在保存策略时就会看到 400，而不是拿到一份放宽了的规则。

修复后金样：`source_ips: "10.42.0.0/29"`，与策略一致。

## 3. F-070（P2）未知字段静默失效

同一个根因的另一半：`ParsePolicy` 用 `json.Unmarshal` 解析，**不认识 `"source"` 也不报错**。
现在改成 `DisallowUnknownFields`，拼错字段直接 400。

顺带发现 r20 的一个用例本身就在传非法 override（`{"hostname":...}`，hostname 走的是独立列），一并修正。

## 5. 判断

这轮值得记的是**发现问题的方式**：不是写测试去验证某个已知行为，而是"把输出打印出来读一遍"。
金样测试的价值一半在回归，另一半就在于它逼你把生成物**当成艺术品看**——否则那段 `rules` 里的
缺失字段永远不会有人注意到。
