# 第 19 轮评审（2026-11-01）— 从"能收到"到"收得对"

r18 的冒烟只证明"设备收到了配置"。本轮要做"改意图 → 收到第二版"，做的过程中
**又发现接口缺失**：网络和成员都不能改。

## 1. F-045（P1）中央网络只能建不能改

对照 2.7.0 路由表，Go 版只有：

```
GET    /api/v1/networks/{id}
DELETE /api/v1/networks/{id}
GET    /api/v1/networks/{id}/members
POST   /api/v1/networks/{id}/members
```

缺 `PATCH /networks/{id}`、`PATCH|DELETE /networks/{id}/members/{device}`。
也就是说：**建错网络名改不了，加错成员删不掉**，只能删整个网络重来。

本轮补齐三个处理器：

| 接口 | 说明 |
|---|---|
| `PATCH /api/v1/networks/{id}` | display_name / network_name / networking_method / virtual_cidr / secure_mode / acl_policy / peer_urls；空名与未知组网方式直接 400 |
| `PATCH /api/v1/networks/{id}/members/{device}` | hostname_override / virtual_ipv4 / override_config；空字符串表示清空覆盖 |
| `DELETE /api/v1/networks/{id}/members/{device}` | 解除绑定；重复删除返回 404 |

成员一律按 **device id** 定位（与 2.7.0 前端一致），内部再用 `GetMemberByDevice` 做租户过滤，
跨租户访问表现为 404 而不是 403——不泄露"存在但不属于你"。

回归 `TestMemberAndNetworkEditing`：改名后列表显示新值、未知设备 404、空 display_name 400、
删两次第二次 404、库里成员数为 0。

## 2. F-046（P2）假设备升级为"断言型设备"

`cmd/smokedevice` 新增 `--expect-network`、`--expect-ipv4`、`--expect-count`，
按 (network, ipv4, hostname) 去重计数，内容不符立即 `CONFIG_MISMATCH` 退出。

冒烟变成两阶段（实拍）：

```
device registered   {"machines":[{"machine_id":"9a7c0000-...","hostname":"smoke-device"}]}
network created     3925b6b2-ba19-45d7-8681-7b95cc15175d
member added        204
member renamed      204
configs received    CONFIG_RECEIVED network=smoke-net virtual_ipv4=10.99.0.1 hostname=smoke-device|
                    CONFIG_RECEIVED network=smoke-net virtual_ipv4=10.99.0.1 hostname=smoke-renamed|
```

这条证据同时说明三件事：意图编译正确（网络名/IP 对）、审批周期会重新下发、修订 CAS 让"同一份配置不重复推"（否则会看到 5 秒一次的重复行）。

## 3. 过程中踩的两个时序坑（脚本侧）

- **改名必须在第一次下发之后**：第一次写成"加成员后立刻改名"，结果第一版配置就带着新名字，
  设备等不到第二版直接超时。改成先 `grep CONFIG_RECEIVED` 等第一版到达再改名。
- 上一轮同样的教训：**顺序敏感的端到端脚本必须显式等待前一个可观测量**，不能靠 `sleep`。
