# 第 110 轮评审（2026-11-01）— "文案都在 copy 表里"是句空话

先跑完整门禁（20 项全绿）。然后回到 R-A，看一条从 r44 就写着、但从没被检查过的规范。

## 1. F-179（P2）92 处内联中文

root.md 与评审记录都写着"界面文案统一放在 `client/src/copy/zh-CN.ts`"。
实际扫描结果：

| 文件 | 内联中文字面量 |
|---|---|
| features/admin/settings-page.tsx | 34 |
| features/admin/users-page.tsx | 18 |
| features/setup/setup-page.tsx | 14 |
| features/account/account-page.tsx | 13 |
| features/settings/appearance-page.tsx | 6 |
| features/auth/login-page.tsx | 3 |
| app/app-shell.tsx | 3 |
| app/protected-shell.tsx | 1 |

共 **92 处**。其中几个页面整页都不引用 copy 表——规范在执行层面早就不成立了。

（顺便记一笔：我第一次用 grep 扫的时候得到 0 处，因为字符类在跨层传递时被转义掉了。
**"扫描结果为 0"必须能被第二条证据佐证**，否则很可能只是扫描器坏了。）

## 2. 务实的选择：先锁死，再迁移

一次性迁 92 处是界面重构，风险大。本轮做两件事：

1. `check-ui` 增加 CJK 规则：组件里出现中文字面量即失败；
2. `scripts/cjk-baseline.json` 记录现有 92 处作为基线，**只许缩小**：
   多一处就红；某文件数量下降却没更新基线也红。

第 2 条的第二个方向容易被忽略：如果只限制"不能变多"，迁移完成一半时基线不会自动收紧，
债务就会原地躺着。现在基线是**进度表**，每迁一处必须同步下调。

## 3. 证据

    ui: 27 components checked, states and labels are complete

往 app-shell 塞一个中文字面量后：

    app/app-shell.tsx:26 contains a literal CJK string; move it to the copy table

审计加入第 16 条变异，现在 16/16 全部可红。

## 4. F-180（P2，MONITOR）剩下的 92 处

并把它登记为 MONITOR——不假装它已经修好。

## 6. 判断

这一轮揭示的是"规范写了，但没有检查"的第二种形态：不是忘了检查，
而是**检查器根本不知道这条规范存在**。CJK 规则补上之后，
root.md 里的"文案统一放 copy 表"这句话才第一次有了对应实现。
