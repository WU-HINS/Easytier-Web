## 1. F-056（P1）删除设备：外键错误 + 泄露驱动原文 + 假成功

`DeleteDevice` 的顺序是"先删 devices，再删 revisions"，**从不删 memberships**：

- 设备还在某个网络里 → `network_members` 的外键挡住 → 500；
- 错误信息 `writeError(w, 500, err.Error())` 原样返回，把
  `FOREIGN KEY constraint failed: network_members` 交给客户端（与 r6 F-019 同类）；
- 设备不存在时 `Exec` 影响 0 行，函数照样返回 nil → **204 假成功**（与 r20 F-049 同类）。

**修复**：单事务内依次删 memberships → devices → revisions，devices 的影响行数为 0 则 `ErrNotFound`；
handler 映射 404，其余错误统一 `"cannot delete device"`。

**回归** `TestDeviceDeleteAndAlias`：带成员关系的设备删除返回 204、成员关系消失、设备消失、
响应不含 foreign key/constraint、二次删除 404。

## 2. F-057（P2）设备重命名与删除的界面

新增 `DeviceActions`：行内重命名（输入框 + 保存/取消）与带确认的删除，
桌面表格与移动卡片共用同一组件。删除确认文案明确写"它在所有网络中的成员关系会一并移除"，
因为服务端就是这么做的。
