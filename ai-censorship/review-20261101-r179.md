# 第 179 轮评审（2026-11-01）— 把说了三轮的规矩做成工具

模式替换命中多处已在这个项目里造成四次事故（r135、r136、r159 的脚本，r181 直接吞掉 udp.go 尾部）。
每次事后我都说"以后要断言唯一"，然后下一次照旧。

## 1. scripts/edit-once.py

用法：edit-once.py <文件> <旧串> <新串>

规则：命中次数必须**恰好为 1**，否则打印实际次数并以非零退出，**不改动文件**。

三个实测：

| 场景 | 结果 |
|---|---|
| 唯一命中 | 应用替换，退出 0 |
| 零命中 | the needle matches 0 time(s) in /tmp/eo.txt; refusing to edit，退出 1，文件不变 |
| 两处命中 | the needle matches 2 time(s) ...，退出 1，文件不变 |

## 2. 为什么这次做成工具而不是再立一次誓

前三次我都记住了教训，但都是在**事后**记住的：动手时手里是 sed/python 一行流，写断言反而更慢。
工具的意义就是把"正确做法"变成"更省事的做法"——三个参数，一条命令，比写 python 内联短。

## 3. 局限（写清楚）

- 它只做字面匹配，不做正则；需要正则时仍要自己保证唯一性；
- 它不校验替换后的文件是否还能编译/通过检查——那是门禁的事；
- 它没有被门禁自动调用，靠我自觉使用。这一条是真的弱点：**工具不会自动生效，习惯才会**。
