## 2. F-175（P2）没有 HSTS

安全头里已经有 CSP、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy、COOP，
唯独没有 `Strict-Transport-Security`。

缺它的后果很具体：HTTPS 部署下，用户点到一个 http 链接，浏览器会照走不误——
这正是 SSL stripping 需要的那一小段窗口。

## 3. 修法：只在真的用 TLS 时发

    if r.TLS != nil || secureTransport {
        header.Set("Strict-Transport-Security", "max-age=15552000")
    }

两个决定：

- `secureTransport` 取自运营方的 `EASYTIER_SECURE_COOKIES`（它本来就表示"本站跑在 https 上"）；
- **不加 includeSubDomains**：控制台常和别的服务同域，这一条会连坐。

## 4. 用例同时验证"该有"和"不该有"

`TestHSTSOnlyOnSecureTransport`：

1. TLS 场景（`newTLSHarness`）必须有 `max-age=`，且**不得**含 includeSubDomains；
2. 明文场景必须完全没有这条头。

第 2 条防的是"一刀切"：局域网纯 http 部署不该被塞一条浏览器会忽略、但运维会困惑的头。

探针：把条件改成恒假，立刻报 `HSTS over TLS = "", want a max-age directive`。
