## 1. R-C 极端碰撞

**已修 F-002**：`CreateAdmin` 改为
`INSERT INTO users ... SELECT ... WHERE NOT EXISTS (SELECT 1 FROM users WHERE role='admin') RETURNING id`，
守卫与写入是同一条语句。8 协程实测：1×201 + 7×409，`admin` 行数 = 1。

**新发现（P2）**：`users.username` 唯一索引与"管理员唯一"是两个约束，
若第一个管理员创建失败（比如用户名已存在），系统仍处于未初始化状态——这是正确行为，但错误文案会把运维引向"用户名重复"而不是"请重试初始化"。

## 2. R-E 渗透 / R-F 越权

**F-012（P1，已修）**：`limiterKey` 无条件采信 `X-Forwarded-For`，攻击者每次换一个假 IP 即可
无限次尝试登录。修复：新增设置 `server.trust_proxy`（默认 **false**），只有显式开启才读该头。
回归：同 IP 轮换 XFF 第 11 次返回 429；开启 `trust_proxy` 后按头区分客户端。

**F-011（P1，已修）**：实例配额原按"当前网络内成员数"统计，用户建 2 个网络即可拿 2 倍配额。
修复：改为 `CountMembersByUser` 全租户计数。回归：配额=1、两个网络各加 1 个成员 → 第二个返回 409 `quota_exceeded`。

**复核未变**：普通用户对 5 个管理端点仍全部 403；管理员自身不可删/不可禁用；
`/admin/users/{id}/password`、`/{id}/oidc` 依然 404（只读管理靠"不存在端点"保证）。

## 3. R-D 红蓝攻防

| 攻击 | 蓝队阻断 | 证据 |
|---|---|---|
| 点击劫持 | `X-Frame-Options: DENY` + `frame-ancestors 'none'` | 冒烟实拍 |
| MIME 嗅探 | `X-Content-Type-Options: nosniff` | `TestSecurityHeaders` |
| XSS（内联脚本） | 引导脚本外置为 `/boot.js`，CSP `script-src 'self'` | `boot js served 200` + CSP 头 |
| Referer 泄露 | `Referrer-Policy: no-referrer` | 同上 |
| 伪造来源绕过限流 | 见 F-012 | 已修 |

**残余（P2）**：CSP 需要 `style-src 'unsafe-inline'`（React 行内样式），若后续改成纯 class 方案可去掉。

## 4. R-B 完整从 0 部署

新增 `scripts/smoke-deploy.sh`，一条命令走完：构建 → 空库启动 → 未初始化探测 → 初始化 → 登录 →
注册 → 管理端 → 响应头 → WS 路由 → 静态引导脚本。**本轮实跑通过**：

```
setup status (before)          {"initialized":false}
gate before setup              409
spa /setup                     200
setup admin                    {"role":"admin","username":"root-owner"}
setup again                    409
admin users                    {"users":[{"id":1,"username":"root-owner",...}]}
register user                  {"role":"user","username":"alice"}
csp header                     Content-Security-Policy: default-src 'self'; script-src 'self'; ...
x-frame-options                X-Frame-Options: DENY
ws route (no upgrade)          400
boot js served                 200
```

**新发现（P2）**：失败路径未纳入脚本（端口占用、只读数据库目录）。已登记 F-014 之外的后续项。
