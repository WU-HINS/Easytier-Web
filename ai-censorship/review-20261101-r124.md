# 第 124 轮评审（2026-11-01）— debug 档什么都不多

换到 R-B（从 0 部署）。这次不是看"能不能起来"，而是看**文档承诺的开关是否真的有效**。

## 1. F-196（P2）EASYTIER_LOG_LEVEL=debug 与 info 输出相同

全仓搜索 `.Debug(` 的调用点：**零**。

也就是说这条摆在 README 与 root.md 里的开关，调低级别之后输出完全不变——
运维以为打开了详细日志，实际上什么都没多。

级别过滤本身也只有一个测试（warn 档），debug/info 之间的边界没人验过。

## 2. 修法

1. 在**会话被拒**的分支加一条 Debug（响应仍保持 "session expired" 的模糊措辞，原因只进日志）；
   这是运维排查"为什么我老是被登出"时最需要的那行。
2. 新增 `TestDebugLevelActuallyShowsDebugLines`：

| 档位 | Debug 行 | Info 行 |
|---|---|---|
| debug | 出现 | 出现 |
| info | 被过滤 | 出现 |

探针把 `Configure` 的级别解析写死为 info：

    debug level swallowed a debug line: ... INFO [TEST] ... info line

## 5. 判断

"可配置"不等于"有效"。一条开关如果从未被任何调用点使用，它就是一个装饰品——
而装饰品在故障现场会变成误导。
