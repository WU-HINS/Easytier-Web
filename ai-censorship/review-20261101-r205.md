# 第 205 轮评审（2026-11-01）— ws 通了，udp 不通（附抓包）

目标要求"ws:// 与 udp:// 控制面验证"。两个都做了，结论相反。

## 1. ws:// 可用（官方 2.7.0 实测）

    easytier-core --config-server ws://127.0.0.1:27303/@up/root-owner …

- 设备上线：machine id 与 hostname 都按传入值出现；
- 白名单自动并网；
- reconcile: pushed=1 skipped=0 failed=0；
- 客户端 instance … started（随后 tun 权限错误，沙箱限制）。

结论：ws 与 tcp 同等可用。此前"官方客户端可接入"只覆盖 tcp，这一格补上了。

## 2. udp:// 不兼容（抓包为证）

先确认服务端确实在监听：

    extra udp listener on [::]:27415

然后把官方客户端指过去，控制台侧**没有任何会话、没有心跳**。用一个 UDP 探针抓到它实际发的包：

    pkt1 len=16 hex=2b05df2c010008006e00d891002de820   （10 秒内约 32 个，完全一样的 16 字节）

也就是说客户端在等一个我们不会给的回答，然后一直重试。我们自己的 udp 传送（u32 长度前缀帧）在自家 e2e 里是通的，
所以缺口在**上游 datagram 的握手/封装**，不在监听本身。

这一轮把"三种传输都说支持"的含糊说法，收敛成一句话：**tcp 和 ws 能用，udp 不能。**
