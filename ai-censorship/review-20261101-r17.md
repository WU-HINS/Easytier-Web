# 第 17 轮评审（2026-11-01）— 装配缝：P0 又出现一次

本轮本来只想落实 r16 的一条建议（reconcile 日志补三元组）。改的时候顺手看了一眼
守护进程的 ticker，于是发现了**这轮最重要的东西**。

## 1. F-041（P0）central 网络配置在生产里永远不会下发

`cmd/easytier-webd/main.go` 里确实构造了 reconciler：

```
enforcer := &central.Reconciler{Store: store, Sessions: manager, Logf: log.Printf}
```

但全仓库（非测试代码）**没有任何一处调用 `ReconcileAll` 或 `Run`**。
ticker 里用的只有 `EnforceQuotaAll`。

后果：真实部署中，管理员建好网络、加好成员，控制台显示一切正常，**设备永远收不到配置**。
2.7.0 的"网络"这个核心需求在 Go 版里是**死的**——但 16 轮测试全绿。

**为什么 16 轮没发现**：所有对账用例都**直接调用** `Reconciler.ReconcileUser`。
测试覆盖了"单元"，没覆盖"装配"。这和 r1 的 P0（主键来源错误）是同一类：
**测试验证了函数，没有验证函数被接上**。

## 2. 修复与三层回归

| 层 | 内容 |
|---|---|
| 装配 | `go enforcer.Run(ctx)` + `Interval: 5s` + 推送侧配额 `MaxInstancesPerUser` |
| 装配守卫 | `TestDaemonStartsTheReconcileLoop`：在 `internal/arch` 里直接读 `main.go`，找不到 `enforcer.Run(` 就失败 |
| 行为 | `TestReconcileLoopPushesWithoutManualTrigger`：启动 `Run` 后**不做任何手动触发**，断言修订被写入 |
| 可观测 | 启动日志 `central network reconciler started (interval 5s)`（实拍已确认） |

## 3. F-042（P2）日志三元组（r16 的建议落地）

`reconcile: pushed=%d skipped=%d failed=%d`——只有"未推送"这一个信息时，
运维无法区分"已经同步"和"推送全失败"。

## 4. 这轮的元教训

- **单元测试全绿 ≠ 功能可用**。真正危险的是"实现了、测过了、但没接上"。
- 这类问题只能靠两种方式发现：**读装配代码**，或者**在真实进程上跑一次端到端**。
  本轮是前者；后者的自动化仍然缺（见下）。

## 5. 仍未补的洞

- `scripts/smoke-deploy.sh` 只验证到"能起来、能初始化、能注册"，**没有验证"设备上线后配置真的下发"**。
  真正的端到端需要脚本里带一个假设备客户端，本轮没做（登记为下一步）。
