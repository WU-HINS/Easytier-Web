# 第 87 轮评审（2026-11-01）— "和冒烟脚本一致"这句话，谁来检查

r86 在 README 里加了"用 curl 走一遍"附录，并写明：

> 请求体与 `scripts/smoke-deploy.sh` 用的是同一套形状，那条脚本每次门禁都会跑，所以它们不会悄悄失效。

问题在于：**这句保证本身没有校验**。任一侧改了字段名，两边就分叉，而文档照旧读起来很对。

## 1. F-151（P2）把保证变成检查

check-readme 新增第 7 条规则：

| 输入 | 断言 |
|---|---|
| README 里每条 `curl -d` 的 JSON 请求体 | 它出现的每个字段名，必须也能在 `scripts/smoke-deploy.sh` 里找到 |

不比较取值（文档用 `MACHINE_ID` 这样的占位符），只比较**字段名**——刚好能抓住重命名。

## 2. 规则自己先撞了两下

| 现象 | 原因 | 修法 |
|---|---|---|
| 报 `mtu` 不在冒烟里 | 覆盖配置是嵌套 JSON，冒烟脚本里写成 `"mtu"`（转义形式） | 比较前把冒烟文本里的反斜杠去掉 |
| 报重复或漏报 | 正则把嵌套的 `}` 也算进外层对象 | 只提取 `"key":` 形式，不解析结构 |

第一次运行时它报了 `mtu`，我一度以为规则写错了——其实是**转义**：文档里写 `{"mtu":1300}`，
冒烟脚本里是同一串字符的另一种书写。去掉反斜杠后两侧一致。

## 3. 负向自测

把 README 里的 `device_ids` 改名成 `devices`（冒烟脚本不动）：

    readme: 1 problem(s)
      README documents a request field the smoke script never sends: devices

恢复后转绿。**这就是那句"不会悄悄失效"的兑现方式。**
