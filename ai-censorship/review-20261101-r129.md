# 第 129 轮评审（2026-11-01）— 28 处把内部错误念给客户端听

r128 的 500 泄露（`bal: seed revision: ... SQLSTATE 23505`）不是孤例。这轮做一次全仓扫描。

## 1. F-202（P2）28 处 500 回显原始错误

    grep -rn "StatusInternalServerError, err.Error()" internal/httpapi/

共 **28 处**（router 12、v3_handlers 10、register 3、oidc 3）。
这些错误大多来自存储层，包装后带着表名、约束名与 SQLSTATE。

r19 曾经逐个修过几个端点，但没有规则阻止新增——于是又长回到 28 处。

## 2. 修法：错误进日志，响应给通用文案

    log.Sub("HTTP").Tag("ERROR").Error("unhandled: " + err.Error())
    writeError(w, http.StatusInternalServerError, "internal error")

28 处统一替换，`httpapi` 全套用例仍通过（说明没有用例依赖那些回显文本——这本身是个好消息）。

## 3. 加规则

`TestServerErrorsNeverEchoTheCause`：扫描 `internal/httpapi`，
凡包含 `StatusInternalServerError` 的行不得出现 `err.Error()`；并要求扫描到至少 10 个 500 站点，防止文件重命名后静默空转。

探针恢复其中一处：

    v3_handlers.go:37 echoes the error on a 500; log it instead

## 4. 一个判断上的取舍

不是所有 `err.Error()` 都该消失：400 里的校验文案（"network_name is required"）对用户有用，必须保留。
所以规则只约束 **500**——那才是"客户端做对了，服务端出问题"的场合，也是唯一会暴露内部结构的状态码。

## 5. 台账

202 项：192 FIXED / 7 ACCEPTED / 3 MONITOR / 0 OPEN。

## 6. 判断

这一轮和 r81（handler 不得嗅探驱动文本）是一对：那条管"读"，这条管"写"。
两条都指向同一件事：**驱动与业务之间要有一层翻译，两个方向都不能漏**。
