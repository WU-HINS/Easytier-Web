# 第 233 轮评审（2026-11-01）— ACL 统计：从"做不到"变成"通路打通"

前几轮我一直说 ACL 统计"需要实例侧 RPC"，只能记缺口。这一轮去翻了 methodindex，
发现设备注册表里就有 api.instance.AclManageRpc，GetAclStats 索引为 1——
我们的 Caller 只要换一个服务键就能问到。

## 1. 实现

| 层 | 改动 |
|---|---|
| legacyview | AclServiceKey（ProtoName/ServiceName = AclManageRpc）+ GetAclStats |
| httpapi | GET /api/v1/machines/{machineID}/networks/info/{instanceID}/acl-stats |
| 前端 | 成员列表对 running 成员显示「ACL 统计」，点开是规则/包数/字节表 |

路由一开始写成 /networks/{instanceID}/acl-stats，与既有的 /networks/info/{instanceID} 冲突，启动即 panic。
挪到 info/ 段之后才合法——这种冲突只有真的注册路由时才会暴露。

## 2. 验证到哪一步

- go test ./internal/legacyview ./internal/httpapi 通过；
- 浏览器里成员列表与面板渲染正常；
- **但设备侧此刻没有运行中的实例**（running_network_instances 为空），没能在真机取到非空 ACL 数据。

台账里这条记为 FIXED，但明确标注"接口未在真机上取到非空数据"。这是本轮最需要你注意的一点。

## 3. 顺带发现：检查器自己有个洞

check-contract 的客户端扫描器认不出带模板字面量的调用，于是新路由被报成"没人调用"。
我没有让它静默通过，也没有伪造调用，而是在 noClientCallIsExpected 里显式登记原因（F-303，OPEN）。
