# 第 150 轮评审（2026-11-01）— 第三轮团队：专审最近十轮的新代码

这次把六位评审的靶子缩到最小：**只看最近十轮写过的东西**（UDP 传输、RPC 去重、成员 PATCH 与它的前端）。
结论是：新代码里确实藏着一条 P1，而且是**确定性死锁**。

## 1. 最重的一条：关停会挂住（F-237，P1）

    Close() {
        l.mu.Lock()
        for key, tunnel := range l.tunnels {
            tunnel.Close()   // -> onClose -> l.detach() -> l.mu.Lock()  同一把不可重入锁
        }
        l.mu.Unlock()
    }

只要有**任何**一条在线 peer，关闭监听器就会永久挂住。这不是竞态窗口，是必然。

为什么几十个用例都没抓到：它们全都写成"先 defer listener.Close()，再 defer tunnel.Close()"，
LIFO 让隧道先关、map 恰好为空——**测试系统性地绕开了这条分支**。
新用例反过来写：故意不关隧道就关监听器。探针把 Close 挪回锁内，立刻就挂：

    Close hung with a live peer mapped; the mutex is not reentrant
