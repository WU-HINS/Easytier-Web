# 第 151 轮评审（2026-11-01）— 收第三轮团队留下的六条

六条 OPEN 里收掉三条，都是"看起来能用、实际有一个洞"的类型。

## 1. F-240：UDP 面终于有了上限

WS 设备通道有 1024 个槽位，UDP 面**一个都没有**——一条未认证数据报就换来一条隧道
外加一整套会话 goroutine，65000 个源端口就能造出同量级的对象，只受两分钟空闲回收约束。

修法：maxUDPTunnels = 1024，且判断放在**创建隧道之前**。
新用例把上限调到 2，第三个对端必须 accept 不到；探针把判断挪到创建之后，用例立刻红：

    the listener went past its tunnel limit

## 2. F-245：开 UDP 但端口为 0，以前什么都不发生

if port > 0 的嵌套分支没有 else：不 bind、不报错、不打日志，界面却显示已开启。
现在启动期直接失败：extra udp listener enabled without a port; set listener.extra_port。

这一条和 r127 的"额外 TCP 监听失败被吞"是同一族的第三次出现——
**配置即承诺，兑现不了就必须失败**。

## 3. F-242：成功提示写了，但永远不会被看到

onSuccess 里先 setSaved(true) 紧接着 onDone()，父级把整块卸载，
role="status" 的那行字从未被绘制、也不会被播报。保存成功与"什么都没改"在界面上完全同形。

同时"只提交改动字段"是用 **props 差异**实现的：编辑期间任何后台刷新都会让未触碰的字段
看起来有改动并被提交——等于把 r141 修掉的 F-228 又请了回来。

修法：初值用 useRef 快照，比较对象是"打开时"而不是"当前 props"；成功后不再立刻关闭。
