# 第 33 轮评审（2026-11-01）— 关停路径

r32 补齐了"运行中出错怎么办"。本轮问另一半：**停止的时候干不干净**。

## 1. F-077 三件此前没有证据的事

| 问题 | 验证方式 | 结果 |
|---|---|---|
| 会话协程会不会泄漏 | `TestShutdownReleasesGoroutines`：5 台设备接入后取消根 ctx + 关闭连接，比较协程数与基线 | 回落到基线+3 以内，**无泄漏** |
| SIGTERM 会不会卡住 | 冒烟新增阶段：`kill -TERM` 后 10 秒内必须退出 | **1 秒内退出** |
| 重启后数据还在吗 | 冒烟新增阶段：同一数据库再起一次，`GET /api/v1/setup` | `{"initialized":true}` |

冒烟脚本现在的完整链路：

```
初始化 → 登录 → 注册 → 响应头 → WS → 设备注册 → 建网 → 加成员 →
改名 → 收到两版配置 → 优雅关停 → 同库重启 → 数据仍在
```

这是"完整从 0 部署体验"这条维度里最后一块拼图：**能部署、能跑、能停、能再起来**。

## 2. F-078（MONITOR）关停并不彻底

`cmd/easytier-webd/main.go` 收到信号后只做：

```go
case <-ctx.Done():
    shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    _ = server.Shutdown(shutdownCtx)
    cancel()
    return nil
```

**没有**关闭 wire 监听器，**也没有**等待会话协程收尾——直接依赖进程退出兜底。

对容器/进程重启没有影响（端口随进程释放），只有在"同一进程内重启控制面"（比如嵌入或测试复用）时才会撞端口。
登记为 MONITOR，不在本轮改动：为它引入 listener/WaitGroup 的代价目前大于收益。
