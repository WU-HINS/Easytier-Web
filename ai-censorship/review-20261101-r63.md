# 第 63 轮评审（2026-11-01）— 日志格式没人验证过

r62 让所有代码都走 `internal/logging`。本轮问：**这个 logger 的输出，真的是文档写的样子吗？**

## 1. F-119（P2）格式是约定，不是事实

文档和评审记录里反复出现的形状：

```
2026-11-01T12:00:00.000Z INFO [HTTP] [Setup] [handleSetup] [L81] ["SUCCESS"] message
```

`logging.go` 里确实拼了这些字段——但**一行测试都没有**。没人验证过：

- 时间戳是不是真的带毫秒和 Z；
- `[L81]` 是不是调用点，而不是 logger 自己的行号；
- `Sub("A").Sub("B")` 渲染成 `[A.B]` 还是只保留最后一个；
- 级别过滤会不会把 `Warn` 也吞掉。

## 2. 写用例时撞到的真问题

第一版用例断言函数名是 `TestFormatMatchesTheDocumentedShape`，结果拿到的是：

```
[HTTP] [Setup] [tRunner] [L1690] ["SUCCESS"] console initialized
```

原因是 `caller()` 用**文件路径**过滤自己：

```go
if strings.Contains(frame.File, "/internal/logging/") { continue }
```

调用方只要文件在这个目录下（比如同目录的测试），就会被当成"自己的帧"跳过，一路跳到 `tRunner`
才停。生产代码不在这个目录里，所以平时看不出来——**这正是"约定没有用例"会掩盖的那类问题**。

修法两步：

1. 改用 `runtime.CallersFrames`（能把内联帧展开，比手数 `skip` 稳）；
2. 过滤条件从"文件路径"改成"**函数名前缀** `internal/logging.`"——只有本包的函数才算自己。

修完输出正确：

```
2026-11-01T00:38:10.355Z INFO [HTTP] [Setup] [TestFormatMatchesTheDocumentedShape] [L25] ["SUCCESS"] console initialized
```

| `TestFormatMatchesTheDocumentedShape` | 逐字段：时间戳能被 `time.Parse` 解析、级别/模块/子模块/函数名/行号/tag/消息 |
