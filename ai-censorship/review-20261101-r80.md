# 第 80 轮评审（2026-11-01）— 同一个错误码，两处写法

r79 把 OIDC 的"先查后插"沉到了 store。按同一条线索继续扫，**注册**是同一个形状。

## 1. F-142（P2）并发注册同名用户

    taken, _ := ExistsByUsername(username)   // 读
    if taken { 409 }
    CreateUser(...)                          // 写

两个并发注册都通过检查，输的一方撞上唯一索引。此时发生的事是：

- 文案**已经**是脱敏的（r19 的成果）：`cannot create the account`，不含表名索引名；
- 但状态码是 **500**——对客户端来说这是"服务器炸了"，不是"这个名字有人用了"。

所以这一轮修的不是信息泄露，是**语义**：一个正常的用户输入冲突被报成了服务端故障。

## 2. 修法与 r79 共用判定

| 层 | 改动 |
|---|---|
| bal | `CreateUser` 遇到 `isUsernameViolation` 时返回 `ErrUsernameTaken` |
| httpapi | 把该哨兵映射成 **409** `username is already taken` |

判定的复用很关键：r79 为 OIDC 写的 `isUsernameViolation` 直接拿来用，两个方言的错误文本都覆盖。
**一个概念只写一次**——否则下次改判定就会漏掉一处。

## 3. 验证（两条，互补）

| 用例 | 层次 | 断言 |
|---|---|---|
| `TestCreateUserReportsDuplicateNames` | store | 重复名得到 `ErrUsernameTaken`，且消息不含 `unique` / `users.` |
| `TestConcurrentRegistrationKeepsOneAccount` | HTTP | 4 个并发注册同名：恰好一个 201、其余 409、库里只有一条该用户名 |

负向自测（把映射删掉）：store 用例报出原始驱动文本，HTTP 用例报出 `registration 0 = 500`。
两条各自覆盖不同的失败形态——一个是泄露，一个是语义。
