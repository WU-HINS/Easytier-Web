# 第 71 轮评审（2026-11-01）— PostgreSQL 的快照有三种结局，只测过一种

r53 补了 SQLite 的快照安全属性（快照先于 DDL、失败即中止）。但 PostgreSQL 走的是完全不同的实现：
**shell 调用外部 dump 命令**，而不是拷文件。三种结局行为各异，此前一种都没测。

## 1. F-129（P2）三段用例

| 配置 | 期望行为 | 此前 |
|---|---|---|
| 不设 `EASYTIER_DB_BACKUP_CMD` | 不产生快照，**对齐继续**（远端库没法快照，不能因此卡死） | 未验证 |
| 设了命令且成功 | 快照文件包含命令输出，且**先于 DDL** | 未验证 |
| 设了命令但失败 | **对齐报错中止**，目标表仍不存在 | 未验证 |

`TestPostgresBackupCommand` 三段全部断言，包括"失败时表确实没被建出来"这条——
只看返回错误是不够的，必须证明什么都没改（和 r53 同一条原则）。

## 2. 顺带把后果写进文档

README 之前只列了 `EASYTIER_DB_BACKUP_CMA...` 一行说明，没讲**失败会怎样**。补上：

> **快照失败会中止启动**：需要改 schema 时，备份写不出来就不执行任何 DDL（宁可起不来也不半途改数据）；
> schema 已是最新时不会备份，所以这条只影响"确实要升级"的那次启动。

这是"文档要说清代价"的一类：`EASYTIER_DB_BACKUP=1` 看起来是个无害的开关，
但配上只读工作目录就会让**升级那次启动**失败。不写清楚，运维会以为是程序坏了。

## 5. 判断

数据库层的三种"快照"路径现在都有用例：SQLite 拷文件（r53）、PostgreSQL 调命令、无命令降级（本轮）。
**同一件事在不同方言下有不同实现时，必须分别验证**——r8（DDL 顺序）和本轮（快照）都栽在这上面。
