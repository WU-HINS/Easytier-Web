# 第 54 轮评审（2026-11-01）— 旧库检测从来没接上

继续扫"实现了但没被真正执行过"的路径。这轮撞到一个**接线错误**，性质和 r17（对账循环没启动）一样。

## 1. F-109（P1）旧库检测是死代码

`dsm` 里写着：

```go
// The legacy detection is intentionally conservative: it only reports, it never
// rewrites data.
legacy, err := detectLegacy(ctx, conn, options.LegacyTables)
report.Legacy = legacy
```

而 `db.OpenWith` 传参时：

```go
report, err := dsm.Init(ctx, conn, dsm.Options{
    Backup: backup,
    DryRun: config.DryRun,
})          // ← 没有 LegacyTables
```

于是 `detectLegacy` 永远收到空列表，直接返回 false；守护进程里那条
`"schema: legacy tables detected; no data was modified"` 日志**永远不会打印**。

后果具体：把一个已经有 2.7.0 数据的库指给 Go 版控制台，它会**在我们的表旁边再建一套表**，
然后报告"全新初始化"，操作者看到空控制台，第一反应是"数据丢了"。

**修复**：在 `internal/db` 定义 `legacyTables` 并传入。清单取自上游
`easytier-web/migrations/20241026_init.sql`：`groups`、`permissions`、
`users_groups`、`groups_permissions`。

**刻意排除 `users`**——我们自己的 schema 也叫 `users`，把它放进去会让每个新库都被判成"旧库"。
这条判断需要对着两边的 schema 才能做出来，也是为什么这个清单必须写死在代码里并注明出处。

## 2. F-108（P2）DryRun 没有用例

`--dry-run` 是运维在升级前预演的开关。若它误执行了 DDL，"只检查"就等于改了生产库。
`TestDryRunReportsWithoutApplying` 断言两件事：计划里**有** create_table，而库里**没有**这张表。

## 3. F-110（P2）环境变量校验

`EASYTIER_DB_DRIVER` / `EASYTIER_DB_DSN` 是唯一无法编译期检查的配置面。
五个用例：缺 driver、未知 driver、缺 DSN、`sqlite3`、`pg` 两个别名。

## 5. 判断

r17 是"实现了但没启动"，F-109 是"实现了但没接线"——**同一类错误的两种形态**。
它们的共同点是：单元测试都在测**函数本身**，没有人测"这个函数在网络里被调到了"。

这类问题的检查成本很低（读一眼传参），但如果没人读，它可以沉默地存在很久。
