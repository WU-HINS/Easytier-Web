# 第 218 轮评审（2026-11-01）— 簇 E 第一批：把"设备视图"挡在适配层外

原版的 10 条设备视图路由（info / config / metas / 停止实例 / 启动 / 校验 / 代理 RPC）是第二套数据模型：
它把"设备"当成一等公民。我们的是"网络 + 成员 + 编译下发"。

## 1. 解耦的做法

    internal/legacyview   ← 只依赖 central 的方法索引常量、rpc、pb

它不认识 Store、不认识 HTTP、也不认识编译期，只做一件事：把 HTTP 的意图翻译成设备能懂的 RPC 调用。
handler 只有形状转换与错误映射（设备不应答 → 502）。

## 2. 本轮落地的 5 条

| 路由 | RPC |
|---|---|
| GET /machines/{m}/networks/info | CollectNetworkInfo（method 4） |
| GET /machines/{m}/networks/info/{i} | 同上，带 inst_ids |
| POST /machines/{m}/networks/metas | ListNetworkInstanceMeta（method 8） |
| GET /machines/{m}/networks/config/{i} | GetNetworkInstanceConfig（method 7） |
| DELETE /machines/{m}/networks/{i} | DeleteNetworkInstance（method 6） |

## 3. 用例

- TestAdapterUsesTheClientServiceMethods：逐条固定 method index、目标服务（WebClientKey）与请求形状；
- TestAdapterRejectsAMalformedInstanceID：非法 UUID 直接拒绝，且**不触发**设备调用（避免把零值 uuid 发出去）。
