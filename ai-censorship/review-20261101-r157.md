# 第 157 轮评审（2026-11-01）— 让设备真的走一次 UDP

上一轮把最后一条 MONITOR 结案了。这一轮回到我自己列的"未实测面"：
UDP 传输上线后，**没有任何一条路径证明设备能通过它完成一次真实会话**。
监听器用例证明的是"帧能收发"，不是"设备能接入并收到配置"。

## 1. 补上客户端那一半

wire 里只有监听侧，设备侧无处可去。新增：

| 新增 | 作用 |
|---|---|
| wire.DialUDP(ctx, addr) | 客户端侧隧道，与监听侧共用 u32 长度前缀帧 |
| udpClientTunnel.IsDatagram() | 让 RPC 层的去重开关在两端一致生效 |

## 2. 让 smoke 走一遍完整会话

cmd/smokedevice 从"tcp 与 ws"扩到"tcp 与 ws 与 udp"；smoke 增加一步：

1. 先 PATCH 成员（改 hostname_override）——必须，因为对账只在 revision 变化时下发；
2. 让设备用 --transport udp 拨到额外监听端口；
3. 断言收到配置。

实跑：

    udp device config              1 revision(s) received

这是这个传输第一次被端到端证明：设备拨入、心跳绑定、会话建立、配置下发。

## 3. 过程中的两个自伤（都当场修了）

| 现象 | 原因 |
|---|---|
| 第一次跑：only 0 of 1 configuration(s) arrived | 忘了 revision 没变化就不会下发，补 PATCH |
| 第二次跑：member renamed for udp returned 400 | curl 的 -d 里内层引号没转义 |

第二个和 README 里那条是**同一类错误**，而且是我在同一个项目里第二次犯。
这次它是被 smoke 自己抓住的（400 不是 204），而不是被读者抓住。

## 4. 台账

247 项：239 FIXED / 8 ACCEPTED / 0 MONITOR / 0 OPEN。

## 5. 判断

"功能已实现"这句话，在这个项目里现在有三档证据：
监听器用例（帧能收发）、端到端会话（设备能接入并收到配置）、门禁里的可红断言。
这一轮把 UDP 从第一档推到了第三档。
