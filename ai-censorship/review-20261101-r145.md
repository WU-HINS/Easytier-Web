## 1. 之前是什么样

管理后台可以打开"额外 UDP 监听"并保存，数据库里也有这一行，
但守护进程启动时只打印一句：

界面还挂着一个"传输层待实现"的橙标。**用户能打开一个什么都不会发生的开关。**

## 2. 实现要点

UDP 没有连接，所以监听器要为每个远端地址**合成一条隧道**：

| 关注点 | 做法 |
|---|---|
| 帧格式 | 与 TCP 完全一致：u32 小端长度 + 编码后的包。这样对端换传输层不需要第二个解析器 |
| 首包 | 某个地址第一次发言时创建隧道并交给 Accept |
| 后续包 | 交给已存在的那条隧道的入站 channel |
| 背压 | channel 满就丢包，而不是阻塞读取协程 |
| 回收 | 空闲 2 分钟回收，且 Accept 无人取时立即丢弃该对端——防止源地址洪泛把 map 撑爆 |
| 畸形包 | 长度不符/解码失败直接丢弃（UDP 对端不可信），不致命 |
| 绑定失败 | 与 TCP 同规则：致命退出，不留下"配置了但没监听" |
