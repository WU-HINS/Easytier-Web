第 50 轮。本轮把最后一个"已知但一直搁着"的 MONITOR 关掉，顺便把五十轮的账理一遍。

## 1. F-078（P2）关停不再依赖进程退出兜底

改之前的关停：

```go
case <-ctx.Done():
    server.Shutdown(5s)
    return nil
```

没有关闭 wire 监听器，也没有等待会话协程——进程退出时内核会收拾，但"同进程内重启"（嵌入、测试复用）
会撞端口，而且走的时候没有任何可观测痕迹。

现在的顺序：

```
log "shutting down"
关闭 tcp / ws 监听器        （先停止接收新连接）
HTTP server.Shutdown(5s)    （等在途请求）
等待会话协程（上限 5s）      （acceptLoop 用 WaitGroup 跟踪）
log "stopped"
```

冒烟脚本新增两个断言：日志里必须出现 `shutting down` 与 `stopped`，
并且退出后同端口重启成功（原本就有）。

## 3. 数字背后，哪些是真的

**真修过的 P0/P1**（有代码变更 + 回归用例）：

- r1 注册用户变管理员（主键来源错）
- r17 对账循环从未启动（功能整体不工作）
- r37 多网络设备每 5 秒重复下发（永不收敛）
- r30 ACL 规则 fail-open（越收紧越宽松）
- r28 临时成员拿到群组密钥
- r31 单个坏网络让整个租户停摆

**只补了证据、产品本就正确**的：r29（override 白名单）、r46（OIDC 绑定守卫）、r47–r49（跨站写、
禁用账户、会话生命周期、JWT 混淆）。这一类占比超过一半——**这正是"多轮多步评审"的常态**：
大部分轮次不是找 bug，而是把"应该没问题"变成"有证据"。
