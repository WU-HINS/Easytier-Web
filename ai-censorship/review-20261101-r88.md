# 第 88 轮评审（2026-11-01）— 密钥不会出现在日志里吗

这轮换了个问题：**如果明天有人不小心把密钥写进日志，谁会拦住他？**

先把现状 grep 了一遍：现有日志里出现的都是 ID、用户名、标签，没有任何密钥值。**今天是干净的**。
但"今天干净"和"明天不会脏"是两件事。

## 1. F-152（P2）两处都只有自觉

| 位置 | 现状 |
|---|---|
| 日志 | 没有守卫：`logger.Info("token" + token)` 会照写 |
| 设置接口 | 返回 `oidc_client_secret_set` 布尔值，但没有断言密钥**不在**响应里 |

## 2. 日志守卫：先剥离字符串，再看标识符

直接的文本匹配会误报——`"setup rejected: missing or wrong setup token"` 只是一句消息。
所以规则是：**先去掉双引号里的内容，再看剩下的代码里有没有叫 secret/password/token/hash/verifier 的标识符**，
且这一行必须是日志调用。

探针验证（临时文件）：

    logger.Info("fine: the word token in a message")     -> 不报
    logger.Info("leaking " + secret)                      -> 报 :8 logs secret
    logger.Warn("cfg token", cfg.Token)                   -> 报 :9 logs Token

## 3. 设置接口：断言密钥不在响应里

`TestSettingsNeverReturnTheClientSecret`：PUT 保存一个显眼的密钥，GET 设置，断言响应体不含它、且 `oidc_client_secret_set` 为 true。

负向自测把密钥塞进按钮文案后，失败信息直接把整份响应打出来：

    the client secret came back in the response: {"...","oidc_button_label":"super-secret-client-value",...}

这条信息本身就说明了为什么值得写这个用例：**泄露会以"某个无关字段"的形式发生**。
