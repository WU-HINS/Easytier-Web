# 第 194 轮评审（2026-11-01）— 网络高级设置与"节点优先"的合并规则

(B) 的第一块：给网络一份可以继承的高级设置，并让节点覆盖它。

## 1. 设计（沿用已有的词汇）

central 里早就有 Overrides（no_tun / disable_ipv6 / multi_thread / latency_first /
proxy_cidrs / listener_urls / disable_p2p / mtu / enable_exit_node / disable_encryption），
一直是"成员 override"在用。这轮把它提升为**两层**：网络存一份（networks.advanced），成员再存一份。

合并规则：逐字段，成员设置则用成员，否则继承网络；切片同理（成员为空则继承）。

## 2. 用例与探针

TestNetworkAdvancedSettingsAreInheritedAndOverridden：网络 mtu=1400、disable_p2p=true、listener_urls 一条；
成员 A 无 override，成员 B override mtu=1200。断言 A 三项全部继承，B 的 MTU 是 1200 且**继承项不被清空**。

探针：MergeOverrides 直接返回网络值 → overriding member mtu = 1400, want its own 1200。

## 3. 这轮自己踩的坑（F-266）

新列是 NOT NULL，而插入时把 nil 指针直接传进去 —— 于是**任何不带高级设置的建网都会失败**。
e2e 立刻红：constraint failed: NOT NULL constraint failed: networks.advanced。
改成 advancedValue()（nil → 空串）后 db 与 e2e 两套全绿。

教训很短：加一列之后必须立刻跑既有套件，而不是等门禁。
