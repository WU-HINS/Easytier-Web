# 第 253 轮评审（2026-11-02）— 队友复核带回来的对比度问题，根因不在配色表

R-A 复核报了 1 个 P2：主按钮文字对比度深色 2.61、浅色 3.56，都低于 AA。
我第一次只在概览页测，**没复现**；换到网络页复现了——是我测得不够。

## 1. 根因

按钮的类名里 `text-primary-foreground` **整条不见了**：

    ... bg-primary hover:opacity-[0.92] h-[...] text-phi-base w-full

`cn()` 是 `clsx` + `tailwind-merge`；merge 按时**前缀**分组，自定义字号 `text-phi-base` 被当成"文字颜色"，
于是它和 `text-primary-foreground` 冲突，后者（出现在前面）被删掉，按钮回落到 body 的 `--foreground`。
配色表本身是对的——`--primary-foreground` 两套主题都达标。**问题在工具把类名吃了。**

## 2. 修法

`extendTailwindMerge` 把 `text-phi-*` 注册成 font-size，两组不再互相覆盖。
实测：深色 **6.74**、浅色 **5.03**。

## 3. 更值得说的是守卫

`check-contrast.mjs` 一直绿——因为它只算 **token 对**，从不看 DOM。
这正是"守卫检查了错的层"：配色表合格，页面照样不可读。

补的断言在 ui-tour 里：读按钮的**计算样式**算比值，并要求 `html.dark` 真的切换过，
否则两次采样会测到同一个主题却都显示 PASS（我第一版就是这样，两次都是 5.03）。

## 4. 顺手修掉的四条 P3

- 「管理」「文档」55 高但只有 16 宽 → 补 `min-w`，实测 55×55；
- 英文列表「0 of」→ `count` 改成 networks；
- 首访必有一条 401（未登录就拉 console-info）→ 登录页与初始化页不再拉；
- 登录页副标题重复两次 → 表单标题下不再重复。

## 5. 页签 ARIA

四个页签补 `id` / `aria-controls` / `tabIndex`，四个面板包成 `role=tabpanel` + `aria-labelledby` + `hidden`。
