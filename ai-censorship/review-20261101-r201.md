# 第 201 轮评审（2026-11-01）— 真机二进制跑通了一半：设备能上线，配置还推不过去

用官方 easytier-core 2.7.0 反复试，把"连不上"先缩小成"心跳被拒"，再缩小成"下发被拒"。

## 1. 关键发现：心跳被拒是因为 proto_name

抓包显示客户端第一帧就是完整的 RpcPacket（帧格式本来就一致），但客户端返回的是

    Invalid method index: 2, service: WebServerService
    InvalidMethodIndex(1, "WebServerService")

根因：官方客户端在 descriptor 里把 proto_name 留空，而我们的注册表按 (domain, proto, service) 三元精确匹配。
修法：Registry.Lookup 先精确匹配，未命中则退化为只按服务名匹配。

## 2. 修完之后的真机结果

控制台 /api/v1/machines 里出现了该设备：machine 11111111-…，版本 2.7.0-8b7f1f01；
成员列表里也出现了它（pending）。

**心跳、设备上报、白名单自动并网，对真机全部生效。**

## 3. 还差最后一步：下发

    reconcile: push … remote error: InvalidService: "WebClientService"

客户端注册了 WebClientService，但我们发的 descriptor 它不认。已加 proto_name 变体回退
（api.manage / api_manage / 空），三种都未命中——说明还差一个维度，很可能是 domain_name。
