# 第 161 轮评审（2026-11-01）— 给上一轮的修复补用例，其中一条补不上

上轮四条修复里，两条本该配可红用例。这一轮去补，结果一半成功一半失败。

## 1. F-252：用例写不出来，如实记录

想法很简单：客户端已连到监听器，再让一个"第三方"套接字往客户端的临时端口发脏包，
然后发一帧合法数据，断言客户端仍能收到。

实测直接失败：

    oversize datagram: write udp 127.0.0.1:37562->127.0.0.1:48521: write: connection refused

原因：客户端用的是 connected socket，内核按四元组过滤——
来自其它源地址的数据报根本进不来，连"脏包"都送不到。

也就是说这条修复**在客户端侧本来就很难被外部触发**（服务端那一侧已经有丢弃逻辑），
但既然我改了代码，就应该说明它现在没有守卫。用例已删，缺口写进账本。

## 2. 判断

这一轮的价值不在于"补上了"，而在于**把补不上的那条明确标成待补，而不是假装它被覆盖了**。

一个没有用例的修复，和一个没有修复的缺陷，在账本上的区别必须写清楚：
前者 FIXED 但缺守卫，后者 OPEN。混为一谈是这个项目最该避免的自我欺骗。
