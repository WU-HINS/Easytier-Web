# 第 62 轮评审（2026-11-01）— 日志格式不能有两种

这个项目把日志格式当接口在维护（HiDNS 风格，`时间 级别 [模块] [子模块] [函数] [行号] [tag] 消息`）。
本轮检查：**有没有绕过它的地方**。

## 1. F-118（P2）对账器用的是标准库 log

`internal/central/reconcile.go` 里：

```go
if r.Logf == nil {
    r.Logf = log.Printf
}
```

全仓只有这一处（其余都用 `internal/logging`）。后果不是功能性的，是**可运维性的**：

- 对账错误以 `2026/11/01 07:04:29 reconcile: ...` 的形式出现，没有级别、没有 tag；
- 按 `[CENTRAL]` 或级别过滤时会把它们漏掉；
- 两种时间格式混在一路输出里。

改成 `logging.New("CENTRAL").Tag("RECONCILE")`，级别用 `Warn`（对账失败是异常，不是信息）。

## 2. 加一条约束，而不是只改这一处

改完就完是不够的——下一个包照样可以 `import "log"`。新增 `TestBusinessCodeUsesTheProjectLogger`：
`internal/` 下（`internal/logging` 自身除外）不得 import 标准库 `log`，不得调用 `fmt.Print*`。

## 3. 初版漏检（值得记下来）

第一版守卫只匹配"独立成行"的 `"log"`，而我自测时写的是 `import "log"` 单行形式——
**守卫通过了，但它其实没在看**。发现方式：自测时临时包没有触发失败。

改成同时匹配两种形式，重新用单行与块式各测一次：

```
internal/tmplog/probe.go imports the stdlib logger; use internal/logging
```

两次都红，删掉后绿。

**这是本轮最重要的一条**：一个"永远绿"的守卫比没有守卫更糟，因为它会让人以为这件事被看着。
