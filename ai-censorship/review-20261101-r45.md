# 第 45 轮评审（2026-11-01）— 关掉挂了 36 轮的 MONITOR

F-027 从 r9 一直挂到现在：**反向代理终止 TLS 时，服务端推导的回调地址是 http，被自己拒绝**。
当时判断"改它需要可信代理白名单"，于是登记为 MONITOR。这轮发现——白名单早就有了（r2 的 %%BT%%server.trust_proxy%%BT%%）。

## 1. 修法：复用同一个信任开关

%%BT%%Server.requestScheme%%BT%%：

%%BT%%%%BT%%%%BT%%go
if r.TLS != nil { return "https" }
if settings.Bool(ctx, KeyTrustProxy, false) && X-Forwarded-Proto == "https" { return "https" }
return "http"
%%BT%%%%BT%%%%BT%%

回调地址与登出地址都改为走它。关键点是**默认不信任**：没打开 %%BT%%trust_proxy%%BT%% 时，
任何客户端都能发 %%BT%%X-Forwarded-Proto: https%%BT%%——如果无条件采信，等于让人自称"我是 https"。

这和 r2 处理 %%BT%%X-Forwarded-For%%BT%% 的姿势一致：**同一个开关管同一类头**，不要出现"XFF 可信、XFP 不可信"的割裂。

## 2. 三种情形都有用例

%%BT%%TestProxySchemeHonoursXForwardedProto%%BT%%：

| 场景 | 期望 |
|---|---|
| 未开 trust_proxy + 头为 https | 仍推导 http（头被忽略） |
| 开了 trust_proxy + 头为 https | 推导 https |
| 开了 trust_proxy + 头为 http | 推导 http（不瞎猜） |

## 3. 顺带补文档

README 增加"反向代理"一节：打开 %%BT%%trust_proxy%%BT%%、转发两个头、保留 %%BT%%Host%%BT%%
（否则回调的 host 校验会失败）。这是部署者最容易踩的一个点，之前只存在于我的评审记录里。

## 6. 判断

这轮值得记的是"MONITOR 不等于放弃"：r9 判断"改它需要白名单"，而白名单在 r2 就做出来了——
**只是因为当时没想到去复用**。隔了三十六轮回头看，代价是零。

如果继续，下一个可复用的是同一个思路：%%BT%%requestScheme%%BT%% 现在只管 OIDC；登录页的
"是否显示 SSO 按钮"用的是 %%BT%%window.location.protocol%%BT%%（前端判断），两者在反代场景下
可能不一致，值得核对一次。
