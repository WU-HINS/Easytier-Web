# 第 40 轮评审（2026-11-01）— 浸泡：设备反复上下线

r16 压了并发、r33 验了关停，但**"跑一段时间之后还稳不稳"**一直没测过。
本轮补上，并且把"改一个网络只推一次"这条核心语义也放进了同一个用例。

## 1. 用例设计

`TestSoakDeviceChurn`：一台设备在两个网络里，循环 N 轮"连接 → 对账 → 断开"。

每轮断言：

- `compile_errors == 0`
- `stopped == 0`（实例集合与意图一致，不该收回任何东西）
- 首轮之后 `pushed == 0`（配置必须收敛，不能反复重推）

循环结束后再检查：

- 累计重复推送必须为 0；
- 协程数回落到基线 +5 以内。

**中途插入一次意图变更**：第 N/2 轮把某个网络改名，断言"恰好 1 次推送"，随后继续收敛。
没有这一步，用例只是把"什么都没发生"重复 15 次。

## 2. 结果

| 配置 | 结果 |
|---|---|
| 默认 15 轮 | PASS（约 1 秒） |
| `EASYTIER_SOAK_ROUNDS=200` | PASS（5.5 秒），无重复推送、无协程增长 |
| 60 轮 + `-race` | PASS，无数据竞争 |

**没有发现缺陷**。这条用例的价值在于把 r37 修的那个 bug（多网络重复推送）变成了**可回归的语义**：
现在如果谁把修订比较改回单值，这个用例会立刻报"re-pushed N times"。

## 3. 参数化

`EASYTIER_SOAK_ROUNDS` 环境变量控制轮数（默认 15，保证门禁快）。章程里补了一行说明，
需要更长时间时手动跑：

```
EASYTIER_SOAK_ROUNDS=200 go test -run TestSoakDeviceChurn ./internal/e2e/
```

## 5. 判断

到这一轮，"持续性"这条线闭环了：**单个请求**（r12 fuzz）、**并发**（r16）、**故障隔离**（r31）、
**异常边界**（r32）、**关停**（r33）、**长时间运行**（r40）。

剩下没测的是"跨进程"（r10 的多副本只做到告警，根因未解）——那是架构级缺口，不是测试能补的。
