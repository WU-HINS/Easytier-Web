# 第 39 轮评审（2026-11-01）— 让"同步状态"可见

r38 把撤销做成真的了。但界面上仍然只有"在线/离线"——**下发失败和还没下发长得一模一样**。
本轮把内部已有的两个事实暴露出来。

## 1. F-087（P2）成员列表补两个字段

| 字段 | 含义 | 来源 |
|---|---|---|
| `running` | 设备心跳里确实上报了这个实例 | `Manager.OnlineInstances` |
| `pending` | 存储的修订 != 当前编译的修订 → 有一次下发在路上 | `DecodeRevisions` + `PlanRevision` |

这两个值此前**只存在于服务端内部**（reconcile 用它决定推不推），从来没有暴露给界面。

界面上现在三种状态可以区分：

```
待下发  -> 修订不一致，对账会推
运行中  -> 设备已上报该实例
（都没有）-> 已同步但设备没跑（例如设备离线）
```

## 2. 顺带做的两件事

- `PlanRevision` / `DecodeRevisions` 从 central 包导出（原本是私有的），
  HTTP 层不再需要自己复制一套哈希逻辑；
- `TestResponseShapesMatchClientInterfaces` 增加了成员条目的键断言——r22 只覆盖了
  machines/networks 两个列表，members 一直是空白。

## 3. 回归

`TestMemberPendingFlag`：新建成员 `pending=true`；按对账的算法写入修订后
`pending=false`。这条用例同时固定了"HTTP 层与 Reconciler 用同一套修订算法"这个隐含约定——
如果哪天两边算法不一致，这个用例会先红。
