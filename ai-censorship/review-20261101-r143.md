# 第 143 轮评审（2026-11-01）— 把最后一个"界面上到不了"补上

root.md 的已知边界里一直挂着一句：成员级 PATCH 端点后端已实现并有用例，但前端没接。
这一轮把它接上，顺带验证上一轮改的"按列更新"在真实 UI 里好用。

## 1. 为什么这条值得单独一轮

后端早有 PATCH /api/v1/networks/{id}/members/{deviceID}，能改 hostname_override 与 virtual_ipv4。
但界面上只有两件事可做：整行删除，或者编辑 override_config 的 JSON。
改一个成员的主机名？只能去数据库里改。

check-contract 的输出一直是证据："routes without a client call (7)"，其中就有这一条。
这个数字每轮都在打印，我却没把它当待办读。

## 2. 做了什么

| 层 | 改动 |
|---|---|
| 客户端 API | api.patchMember(networkID, deviceID, patch) |
| 组件 | 新增 member-editor.tsx：两个输入框 + 保存/取消 + 错误与成功提示 |
| 列表 | 每行加"改名称/IP"入口，与既有的"高级"入口并列 |
| 文案 | copy 表补 7 条，仍然零内联 CJK |

**只提交被改动过的字段**：MemberEditor 会比较初值，只有真的变了才放进 patch。
这与上一轮 F-228 的"按列更新"是同一套语义——UI 不制造不必要的写。
