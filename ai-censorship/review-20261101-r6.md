# 第 6 轮评审（2026-11-01）

## 1. R-E 渗透：F-019 驱动错误外泄（P1）

**复现**：给网络重复添加同一设备，或添加一个不存在的设备 —— 返回 **500**，
响应体回显 `UNIQUE constraint failed: network_members.user_id, ...` 之类的驱动原文。

**为什么是 P1**：任何已登录用户都能把内部表名、列名、约束名打出来（信息泄露），
同时 500 掩盖了真实语义（冲突 vs 不存在），客户端无法区分。

**修复**：
- `bal.classifyInsertError` 把 SQLite / PostgreSQL 的约束错误映射为
  `ErrMemberExists` / `ErrDeviceNotFound`，其余统一为
  `bal: add member failed`，**不再带驱动原文**。
- 接口层先用 `GetDevice` 校验归属，未知设备直接 404；同请求内重复 device_id 直接 400，不碰数据库。
- 回归额外断言响应里不得出现 `unique` / `constraint` / `network_members` / `sqlstate`。

## 2. R-C 极端碰撞：F-020 批量写入非原子（P1）

**复现**：一次请求加 2 个设备、第二个不存在 → 接口返回失败，但第一个已经落库。
用户看到"失败"，库里却多了一条成员。

**修复**：`bal.AddMembers` 改为单事务，任一失败整体回滚；保留 `AddMember` 单元素包装。
**回归**：混合批次（合法 + 未知）提交后断言成员数 = 0；再提交合法批次断言 = 2。

## 3. R-A 前端美观：F-021 深色模式对比度不足（P1 无障碍）

这条维度此前只有"看起来还行"的判断，本轮补上可计算证据：新增
`scripts/check-contrast.mjs`，从 `tokens.css` 解析 HSL token 并计算 WCAG 对比度。

第一次运行就抓到：

```
dark theme  form control boundary  input / card  2.71:1  (min 3:1)  FAIL
```

深色下输入框边框几乎不可见（WCAG 1.4.11 要求 UI 组件边界 ≥ 3:1）。
把 `--input` 由 `215 24% 38` 调整为 `215 22% 47` 后为 **3.76:1**，
浅色/深色 10 组检查全部通过，脚本已纳入审核团门禁。
