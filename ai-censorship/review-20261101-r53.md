# 第 53 轮评审（2026-11-01）— 两条"每次启动都会跑"的路径

本轮继续找"还没被真跑过"的路径，挑了两条都在启动阶段的：**快照**与**额外监听**。

## 1. F-106（P2）快照必须先于 DDL，失败必须中止

`dsm.Align` 的顺序是：算计划 → **快照** → 执行 DDL → 校验。代码注释写着
"A failing snapshot must not silently proceed into a schema change"——但它没有用例。

这条一旦写反（先 DDL 后快照），后果是：升级失败时用户既没有新结构、也没有旧数据。

`TestBackupRunsBeforeSchemaChange` 两个方向：

| 场景 | 期望 |
|---|---|
| 缺表的旧库 + 正常备份目录 | 对齐成功，`report.BackupPath` 非空且文件真的存在 |
| 缺表的旧库 + 不存在的备份目录 | 对齐**报错**，且目标表**仍然不存在**（证明 DDL 没跑） |

第二个断言是关键：只看"返回错误"不够，必须证明"什么都没改"。

## 2. F-107（P2）额外 TCP 监听从来没起来过

v3 需求里有"面板端口始终提供 WS；管理员可决定是否额外开 TCP/UDP"。校验用例有（r21 的端口范围），
但**没有任何用例真的去连那个端口**。

冒烟新增两段：

```
extra listener enabled         200
...
extra listener open            18621
```

顺带暴露了一个此前没说清的行为：**额外监听只在启动时读取设置**，运行期改完不重启不会生效。
这是合理的实现（监听器不在请求路径上重建），但界面没告诉管理员。已在设置页补一行说明。

（UDP 那项界面上本来就挂着"传输层待实现"的徽标——这条一直如实标注着。）

## 3. 过程中踩的坑
