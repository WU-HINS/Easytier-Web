# 第 28 轮评审（2026-11-01）— 逐字段对齐上游编译器

r27 用上游源码确认了地址编码。本轮把同样的方法用到**编译器本身**：
把 `easytier-web/src/central_network/compiler.rs` 里构造 `NetworkConfig` 的那段
和我们的 `buildConfig` 逐字段对照。

## 1. 逐字段对照结果

| 字段 | 上游 | 本实现（改前） | 结论 |
|---|---|---|---|
| `instance_id` | 网络 id | 按 (network,device) 派生 | 差异，登记 F-066 |
| `dhcp` | `address.is_none()` | 不设（恒分配） | 等价 |
| `virtual_ipv4` / `network_length` | 有 | 有 | 一致 |
| `hostname` / `network_name` / `networking_method` / `peer_urls` / `public_server_url` | 有 | 有 | 一致 |
| `network_secret` | **仅非临时成员** | 总是下发 | **不一致（F-065）** |
| `secure_mode` | 临时成员用凭据密钥 | 只按网络开关派生 | **不一致（F-065）** |
| `managed_credentials` | secure 且非临时时下发 | **完全不下发** | **不一致（F-065）** |
| `acl` | 有 | 有 | 一致 |

## 2. F-065（P1）两个后果

1. **持凭据的临时成员永远连不上**：secure 网络要靠 `managed_credentials` 才知道该接纳哪些凭据，
   我们一个都没下发；同时核心侧没有密钥可用。
2. **临时成员拿到了群组密钥**：上游对临时成员显式 `(!temporary).then(...)`，我们照发。
   等于把长期密钥交给一个本该只有短期凭据的设备——这既是功能错，也是安全错。

**修复**：`Compile` 增加 credentials 入参（两个调用点各自从 `ListCredentials` 取），
`buildConfig` 按上游规则分支：

```
临时成员:  NetworkSecret=nil, SecureMode{Enabled, LocalPrivateKey=凭据密钥}, ManagedCredentials=空
普通成员:  NetworkSecret=网络密钥, SecureMode{Enabled, LocalPrivateKey, LocalPublicKey},
           SecureMode 网络再下发 ManagedCredentials（id/secret/groups/allow_relay/proxy cidrs/expiry/reusable）
```

**回归** `TestCompileMatchesUpstreamCredentialRules`：两个成员（普通 + 凭据）各断言上述三件事。
改前该用例必然失败（managed_credentials 为空）。

## 3. F-066（MONITOR）instance_id 语义差异

上游用**网络 id**，我们按 (network, device) 派生。核对核心代码后确认：`instance_id` 是实例的本地标识
（`config.set_id(inst_id)`），网络匹配靠 `network_name` + `network_secret`，**不影响组网**。
登记为差异而非缺陷，理由写在台账里。
