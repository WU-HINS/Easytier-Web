# 第 180 轮评审（2026-11-01）— 想给审计脚本加一条用例，先确认它不是本来就红

计划：给 audit-gates.sh 增加一条 editor 变异（删掉 advanceBaseline 调用，检查器必须红），收掉 F-260。
动手前先跑了一遍审计脚本，结果：

    result: FAIL (16 checks audited)
    BROKEN  single admin index (checker still fails after restore)
    BROKEN  quota inside the transaction (...)

四条 go 用例全部 "checker still fails after restore"。

## 1. 虚惊一场

原因是我直接在当前 shell 跑脚本，没有导出 Go 工具链—— 不在 PATH，
所有 go test 用例必然失败，于是被判成"变异后仍然失败"。
带上工具链重跑：

    result: PASS (16 checks, each shown to fail when its subject breaks)

**审计脚本本身是健康的；错的是我的调用方式。**

## 2. F-260 仍未收

加用例时 python 拼接又踩了反斜杠转义（第 N 次），脚本没被改动。
本轮不做未验证的改动，F-260 保持 OPEN，并把"调用审计脚本必须带 Go 环境"记在这里。

## 3. 判断

这一轮几乎没产出，但它避免了一个更坏的结果：**在不带环境的情况下跑审计，看到一片 BROKEN，
很可能误判为"脚本坏了"，然后去改一个本来没坏的东西。**

以后跑任何 go 相关脚本，先把 PATH 导出来——这条已经写进环境行，但显然我还需要再记一次。
