# 第 247 轮评审（2026-11-01）— 给 CI runner 配上 tun

之前 CI 对数据面只做"检测 + SKIP"。这一轮让它真的能跑。

## 1. 缺的是什么

GitHub 托管 runner 是完整虚拟机，但两件事缺：`/dev/net/tun` 设备节点不存在；非特权 runner 用户没有 CAP_NET_ADMIN。

## 2. 怎么做

| 步骤 | 内容 |
|---|---|
| 建节点 | modprobe tun（按需）+ mknod /dev/net/tun c 10 200 + chmod 666 |
| 给能力 | setcap cap_net_admin+ep 作用在 python3（tun-check 用它问内核）与 ET_BIN（easytier-core 用它建接口） |
| 验收 | 仍然跑 `scripts/tun-check.sh`，以内核的回答为准；失败退出 3 |

给解释器加能力只在一一次性 CI 虚拟机上可接受，README 已写明"不要复制到共享机器"。

## 3. 工作流

新增 `data-plane` job：拉 v2.7.0 官方客户端 → provision → `overlay-smoke.sh`，失败时上传日志。
**provision 失败判红**，smoke 返回 3 也判红——一个专门验证数据面的 job 静默跳过，等于把红灯换成绿灯。

## 4. 我验证到哪一步

- YAML 用 pyyaml 真实解析：三个 job、步骤顺序、bin 输出引用都对；
- `ci-tun-setup.sh` 在本沙箱（无 sudo）运行 → "no sudo on this runner; cannot provision"，exit 3；
- **特权路径没有实测**：本沙箱没有 sudo，也没有 CAP_NET_ADMIN。这条只能等 CI 跑一次给答案。

## 5. 需要你确认的

第一次 CI 跑完请看 `data-plane` job：绿 = 数据面通了，F-283 可关；
红且停在 provision = runner 权限模型与预期不同；红且停在 overlay smoke = 代码问题，日志已作为 artifact 上传。
