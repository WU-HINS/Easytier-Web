# 第 217 轮评审（2026-11-01）— 簇 C：配置 ⇄ TOML，单独一层

原版有两个端点：generate-config（配置 → TOML 文本）与 parse-config（TOML → 配置）。
缺失意味着运维没法导出或粘贴一份配置。

## 1. 为什么新开一个包

最省事的写法是在 handler 里直接拼 TOML。但那样字段定义会出现在两个地方
（编译期一份、导出时一份），这正是"越写越缠"的开始。所以：

    internal/configtext   ← 只依赖 pb 与 toml 库，不碰 DB、不碰 HTTP

里面只有 Document（TOML 形状）、FromNetworkConfig / ToNetworkConfig / Dump / Parse。
handler 只负责请求/响应形状，没有业务字段。

## 2. 与上游对齐的一个细节

上游这两个端点**不用状态码**表错误，而是 200 + error 字段，前端把错误显示在编辑器旁。
我们照做——兼容层不该在错误语义上自作主张。

## 3. 用例

TestConfigRoundTripsThroughToml：给一份配置（hostname / ipv4 / network_name / secret / mtu / no_tun / peers / listeners / proxy）→
生成 TOML → 把 TOML 喂回 parse → 断言 hostname、ipv4、network_name、peer、proxy 都还在；
再喂一段坏 TOML，断言仍是 200 且带 error。
