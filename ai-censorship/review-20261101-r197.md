# 第 197 轮评审（2026-11-01）— 给网络高级设置开一扇门（API）

前几轮把数据模型、合并规则、限速、白名单都做完了，但**管理员没有入口**：
只能直接改库。这一轮补 API。

## 1. 端点

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | /api/v1/networks/{id}/advanced | 原样返回存储的 JSON 串 |
| PUT | /api/v1/networks/{id}/advanced | 校验后整段替换；空串表示清空 |

校验分两步：先 ParseOverrides（结构合法），再查白名单规模（上限 256 条、单条 128 字符）。
后者不是洁癖：对账每轮会遍历白名单 × 设备数，无界名单等于开一个放大器。

## 2. 用例（四条断言）

1. PUT 合法 blob → 204，GET 能读回 mtu 与限速；
2. PUT 非法 JSON → 400；
3. PUT 300 条白名单 → 400；
4. **被拒的载荷不得覆盖已存值**（重新读库比对）。

探针：删掉白名单规模校验 → oversized whitelist = 204, want 400。

## 3. 判断

第 4 条断言是这一轮最该有的：验证拒绝时，比验证接受更重要——
一个"返回 400 但已经写进去了"的接口，从调用方角度看和成功没有区别。
