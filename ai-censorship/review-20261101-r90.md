# 第 90 轮评审（2026-11-01）— 从"逐个端点"到"扫一遍"

r88 用一条用例守住 OIDC client secret，r89 又用一条守住网络密钥。两条都是**逐个端点**写的。
问题在于：下一个新端点不会有人记得再写一条。

## 1. F-154（P2）缺一条通用防线

这轮的用例不再盯着某个端点，而是**扫一遍控制台用到的全部读接口**：

| 类别 | 端点 |
|---|---|
| 概览 | console-info、summary |
| 设备 | machines、machines/blocked |
| 网络 | networks、networks/{id}、members、credentials、acl-policy、members/{id}/config |
| 账户 | account/oidc |
| 管理 | admin/users、admin/settings |
| 其它 | rpc-capabilities |

共 14 个，逐个断言响应体不含**两个已知密钥**：

1. 建网时显式指定的网络密钥（这样才知道要找什么）；
2. 创建凭证时返回的那一个（唯一一次返回，之后永不再现）。

## 2. 负向自测

把 `network_secret` 塞进成员列表（r89 那条用例**覆盖不到**的位置）：

    /api/v1/networks/45cfcab1-.../members leaked a secret:
    {"members":[{"device_id":"beef7000-...","hostname":"node",...,
                "network_secret":"NET-SECRET-MARKER-9f1",...}]}

立刻红，而且指名的正是那条新加入的字段。**这说明"扫一遍"能接住"逐个端点"接不住的东西。**

## 3. 三条用例的分工

| 用例 | 覆盖 | 适合拦什么 |
|---|---|---|
| `TestSettingsNeverReturnTheClientSecret` | 单一端点 | 设置接口的字段重排 |
| `TestNetworkSecretNeverLeavesTheServer` | 四个网络端点 + 库中值校验 | 网络材料的"顺便带出" |
| `TestNoEndpointEchoesKnownSecrets` | 14 个读端点 × 2 个密钥 | **新增端点**带来的未知泄露 |

前两条是"我盯着这个点"，第三条是"我盯着所有点"。

## 6. 判断

"逐个端点"的断言会随着端点增长而失效；"扫一遍"的断言会随着端点增长而**变得更值钱**。
两者的成本差不多，但后者是随规模复利的。
