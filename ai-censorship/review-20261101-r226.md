# 第 226 轮评审（2026-11-01）— ACL 从 JSON 文本框变成规则构建器

原版 AclPolicyTab 有 494 行：规则表、动作、协议、源/目标、端口、默认动作、启用开关。我们只有一个 textarea。

## 1. 做法：先抽模型，再写界面

新增 acl-model.ts，只放纯函数：

- parsePolicy / policyToJson：与服务的 Policy/Rule/Selector/ProtocolTarget 一一对应；
- selectorsToText / textToSelectors：any 或逗号分隔 CIDR；
- protocolsToText / textToProtocols：tcp:80,443; udp:53；
- newRule：新建一条允许规则。

面板只负责渲染与调用，两种视图（规则 / JSON）写的是同一份结构，切换不会丢字段。

## 2. 浏览器实测

添加一条「deny-ssh」：动作 deny、源 10.0.0.0/8、协议 tcp:22，保存后从服务端读回：

- default_action = deny
- 新规则 action = deny、protocols = tcp:22、sources = cidr 10.0.0.0/8

## 3. 顺手抓到的一个真 bug（F-295）

保存后服务端库里出现两条 id 都是 rule-1 的规则。原因：newRule 用自增计数器，每次页面加载从 1 开始。
改成随机 id，并在载入时给重复 id 追加后缀；实测保存后变为 rule-1 / rule-1-2，唯一性通过。

这个 bug 只有在"看服务端真正存了什么"时才暴露——界面本身两种 id 都渲染得出来。
