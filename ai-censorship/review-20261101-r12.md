# 第 12 轮评审（2026-11-01）— 换前提：恶意协议输入

前 11 轮所有协议测试都是"正确地发包"。本轮换成对手视角：直接往控制面写畸形帧。

## 1. F-030（P1）分片重组可被用来耗尽内存

**代码事实**（`internal/rpc/mux.go`）：

- `feed` 对每个新 `transaction_id` 执行 `make([][]byte, p.TotalPieces)`，而 `total_pieces` 上限是 **32768**；
- `mergers` 以攻击者自选的 `transaction_id` 为键，**没有数量上限**；
- `SweepMergers` 写好了，但**从未被调用**（全仓库无生产调用点）。

于是单个恶意 peer 只要连发 `{total_pieces: 32768, piece_idx: 1, 新 transaction_id}`，
每条就能钉住约 786 KB 的切片头，且永不释放。

**修复**：

| 手段 | 值 |
|---|---|
| 分片容器 | 改为 `map[uint32][]byte` 懒分配（不声明就不占） |
| 并发重组上限 | 每 mux 64 个 |
| 单个重组体积 | 4 MB |
| 全局在途体积 | 16 MB |
| 过期清理 | `Run` 内每 5 秒 `SweepMergers(10s)` |

**回归** `TestPartialPacketsAreBounded`：灌 200 个恶意分片后断言 `MergerCount() <= 64`，
随后一个 3 片、4 KB 的**合法**分片请求仍然成功——上限不能把正常路径也掐死。

## 2. F-031（P2）空闲连接永不释放

只完成握手、之后不再说话的连接（半开、慢速攻击、设备断电但内核缓冲未清）会永久占住 goroutine 与 fd。
新增**会话空闲看门狗**：超过 `heartbeat timeout` 没有收到任何入帧就关闭隧道并记日志
（`[SESSION] [Idle] ["CLOSE"]`）。

**回归** `TestIdleTunnelIsClosed`：握手 + 一次心跳后静默，6 秒内连接被服务端关闭。

## 3. 一处行为变更（需要记录）

r11 观察到"设备静默后会话仍在、只是离线"。加了看门狗后，**静默超过 timeout 会被直接断开**，
会话随之被回收。这是有意的收紧（否则资源泄漏），但确实改变了 r11 记录的语义，
所以 `TestSilentDeviceIsExpired` 已改写为"静默设备不得被计为在线，残留由 sweeper 回收"，
不再断言"会话必须还在"。**旧结论没有被悄悄保留**。
