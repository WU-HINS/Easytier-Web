# 第 108 轮评审（2026-11-01）— 读路由没有守卫

先跑完整门禁（20 项全绿）。然后补上路由守卫的最后一块。

## 1. 已有三块，缺第四块

| 守卫 | 管什么 | 引入于 |
|---|---|---|
| `TestAdminRoutesRequireTheAdminWrapper` | 管理路由必须套 requireAdmin | r102 |
| `TestTenantTablesAreAlwaysQueriedWithAUser` | 查询必须带 user_id | r103 / r104 |
| `TestCrossOriginGuardCoversEveryMutatingRoute` | 写请求必须过跨站守卫 | r107 |
| 读路由必须套 requireUser | 本轮 | r108 |

前三块都是"写"或"数据"侧。**读**侧一直没人看：新增一个 GET /api/v1 路由忘记套 requireUser，
它就会把租户数据直接交给任何能连上端口的人，而现有用例只覆盖已知路径。

## 2. F-177（P2）修法

`TestReadRoutesRequireASession`：从 `router.go` 解析所有 GET /api/v1 路由，
除四条明文允许公开的（`/setup` 与 OIDC 三段）外，必须出现 `s.requireUser(` 或 `s.requireAdmin(`，
并要求受保护读路由数不少于 15（防空转）。非 API 路径（`/healthz`、`/@up/*`、SPA）天然跳过。

## 3. 探针

去掉 `GET /api/v1/machines` 的外壳：

    GET /api/v1/machines is registered without requireUser or requireAdmin

## 4. 这条用例写得很费劲（值得记）

| 现象 | 原因 |
|---|---|
| 文件里留下占位符 | 替换不完整 |
| 三次 string literal not terminated | 模板里的换行与转义引号跨层传递时被吃掉 |
| 误报 `/healthz`、`/@up`、`/` | 守卫范围没限定在 /api/v1 |

最后改用 Go 的 rune 字面量来产生引号字符，问题才彻底消失——
**能用语言特性绕开转义时，就别跟转义较劲**。

误报那一次其实有价值：它证明守卫确实在读路由（否则不会看到这几条）。
