# 第 252 轮评审（2026-11-01）— 把"使用体验"的三个问题修掉

上一轮测评留下三条：报错说英文、手机上点不到、空态不给下一步。这一轮全修了，并且每条都留了守卫。

## 1. 报错说人话（P2）

之前：在「虚拟网段」里填错 → 界面显示 `virtual_cidr "999.1.1.1/99" is not a valid CIDR`
现在：中文「虚拟网段「999.1.1.1/99」不是合法的网段」，英文 Subnet "…" is not a valid subnet

做法是让错误**带着结构**走，而不是带着句子走：

| 层 | 改动 |
|---|---|
| 服务端 | `fieldError{Code, Field, Value}`；`writeFieldError` 输出 `{message, code, field, value}` |
| 客户端 | `ApiError` 带三者；`describeError(error, copy)` 按 `copy.errors` 查表，`{field}` 用界面的词 |
| 收敛 | 23 处 `(x.error as Error).message` 全部替换 |

一个细节：文案表里 `fields.display_name` 一开始写成「网络名称」，而表单标签是「名称」——
**同一件事两个词**，等于没修好。已对齐成「名称」/「Name」。

## 2. 手机上点得到（P3）

「管理」（网络列表唯一入口）和「文档」原来 16×21px，现在 55px。
ui-tour 在 390×844 下断言 ≥40px，实测 `[{"text":"文档","h":55},{"text":"管理","h":55}]`。

## 3. 空态给出下一步（P3）

「尚无设备」→「尚无设备。在设备上运行 easytier-core --config-server 即可接入。」
「还没有网络」→「还没有网络。创建一个网络后，把设备加进来就能开始组网。」

## 4. 守卫

新增 `scripts/check-errors.mjs`：任何组件再写 `(x.error as Error).message` 就红；进 gate 与 CI。
配合 ui-tour 的两条断言（中文报错含「虚拟网段」、不含 `virtual_cidr`；移动端主操作 ≥40px），
这三条以后都不会静默退回。

## 5. 结果

ui-tour **27 条全绿**（新增 3 条 UX 断言）。这一轮的教训是：**体验问题也能变成断言**，
只要把它写成"界面上必须出现/不得出现什么"。
