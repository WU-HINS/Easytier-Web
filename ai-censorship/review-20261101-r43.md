## 1. F-092（P2）README 教了一个不存在的用法

README 的快速开始写着：

```bash
go run ./cmd/easytier-webd --seed-user admin --seed-password admin
```

参数确实存在（v2 遗留），但实测下来它做的事已经没有意义：

| 步骤 | 结果 |
|---|---|
| 启动带 `--seed-user` | 日志打印 "seeded console user admin"，账号建出来了 |
| `GET /api/v1/setup` | `{"initialized":false}` |
| 用这个账号登录 | **409 setup_required** |
| 再跑 `POST /api/v1/setup` | 201，正常创建管理员 |

也就是说：种子用户**永远登不进去**，只会在库里留一个多余账号；而 README 让新用户以为这是正路。
这正是 r42 修的那个"找不到控制台状态"的同一类问题——**文档引导的路径和真实路径不一致**。

**修复**：删掉两个参数与 CLI 表格里的那一行；快速开始改成"启动 → 打开页面 → 在 /setup 创建唯一管理员"，
并说明初始化前除 `/api/v1/setup` 外一律 409。

## 2. F-093（P2）自动建号绕过注册策略

`--allow-auto-create-user` 会让**任何**未知设备 token 直接建出一个账号，绕过：

- 管理员设置的"关闭注册"（`registration_open=false`）；
- 保留用户名列表。

默认关闭，所以不是活漏洞；但一个"为了接入方便"打开的开关，实际是把注册策略整个旁路了。

**修复**：`LocalAuthenticator` 增加策略钩子，cmd 注入"注册开关 + 用户名校验"；
`TestAutoCreateRespectsPolicy` 覆盖三种情形（策略拒绝不建号、允许才建、总开关关闭仍挡住）。
