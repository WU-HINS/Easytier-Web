# 第 36 轮评审（2026-11-01）— 安全模式矩阵与悬空凭据

上一轮说"补 managed_credentials 在 secure_mode 关闭时必为空的断言"。查这条时把安全模式的
四种组合、以及核心的一条硬性不变量一起核对完了，并顺手挖到一个"删凭据后设备起不来"的问题。

## 1. F-084 核心的不变量：没有 network_secret 就不许配 managed_credentials

`easytier-core/src/instance/config.rs`：

```rust
if !managed_credentials.is_empty() && identity.network_secret.is_none() {
    anyhow::bail!("only admin nodes with a network_secret can configure managed credentials");
}
```

我们的实现恰好满足：managed_credentials 只在"非临时成员 + 安全模式"时下发，而此时一定带着 network_secret；
临时成员不带 secret 也不带 managed_credentials。

`TestSecureModeMatrix` 把四种组合钉死：

| 组合 | secure_mode | local key | managed_credentials | network_secret |
|---|---|---|---|---|
| 普通 | 不设 | — | 0 | 有 |
| 普通 + 安全模式 | enabled | 派生 | 1 | 有 |
| 临时 + 安全模式 | enabled | 凭据密钥 | 0 | **无** |
| 临时 + 非安全模式 | enabled | 凭据密钥 | 0 | **无** |

最后一行值得注意：**临时成员即使网络没开安全模式，也会以凭据身份启动**——
这是上游的语义（凭据成员用 NetworkIdentity::new_credential），不是我们额外的行为。

## 2. F-083（P2）吊销凭据之后，那台设备就再也起不来了

`DELETE /networks/{id}/credentials/{cid}` 只删凭据行，成员行里的 `credential_id` 仍然指着它。
之后编译：

- 找不到凭据 → `secret = ""` → 下发的配置里 `secure_mode.local_private_key` 是空串；
- 核心 `normalize_secure_mode_config` 解析空串失败 → 实例起不来；
- 控制台侧只看得到一条 `reconcile failed`，错误文本来自设备，指向性很差。

**修复**：编译期发现临时成员引用了不存在的凭据，直接报
`member <device> references credential <id> which no longer exists`。
这条错误会通过 `/networks/{id}/members` 的 `compile_error` 显示在成员面板上，
管理员一眼能看出该把这条成员删掉或换凭据。

没有选择"吊销时级联删除成员"——那会让一次误点悄悄删掉成员关系；也没有选择"吊销时拒绝"——
凭据是访问权，吊销必须立即生效。当前做法是**吊销照常生效，但残留关系会被明确报告**。

## 3. 顺带确认

`SecureModeConfig` 允许客户端提供 `local_private_key`（核心只校验 pubkey 与它一致），
所以"按 (网络密钥, 设备) 派生稳定密钥"是合法且优于上游的——上游不提供密钥，核心每次启动随机生成，
节点公钥会随重启变化。这条差异在 r28 已有记录，本轮再次确认无副作用。
