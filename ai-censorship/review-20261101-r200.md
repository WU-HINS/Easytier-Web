# 第 200 轮评审（2026-11-01）— 下载真机二进制，跑出来的第一个结论是"连不上"

按要求把二进制完整下载下来：官方 v2.7.0 发行包，解包后

    easytier-core 2.7.0-8b7f1f01
    easytier-cli  2.7.0-8b7f1f01

（沙箱没有 unzip，用 python 解包；core / cli / web / web-embed 四个都在。）

## 1. 实测：两种传输都失败

| 传输 | 现象 |
|---|---|
| tcp://127.0.0.1:rpc/root-owner | 客户端打印 Web client started，随后控制台连续出现 wire: tcp read header: EOF |
| ws://127.0.0.1:http/@up/root-owner | 控制台打印 device channel opened，随即 1006 abnormal closure |

两次请求 /api/v1/machines 都是空数组——心跳一次都没到达。

## 2. 根因（读上游源码，不是猜）

easytier/src/web_client/mod.rs：客户端不是"连上就发 RpcPacket"，而是通过
easytier_core::management::WebClient + ManualTunnelConnector 建立 EasyTier 自己的 tunnel
（tunnel/raw 帧，含握手），再在隧道上跑管理协议。

我们的控制面是自定义 u32 长度前缀帧 + RpcPacket，只有自家 cmd/smokedevice 会说这种话。
所以"协议已对齐"这句话，此前只是照 .proto 推的，没有任何客户端验证。

## 3. 处理

- F-272 记为 OPEN（P1），写明复现方式与根因；
- root.md 的已知边界从"未实测"改成"实测不通过"；
- scripts/real-instance-check.sh 保留，作为修好之后的回归入口。

## 4. 判断

这一轮的价值全部在负面结果上：一个能自动跑的检查，第一天就推翻了我们自己的结论。
如果继续只有假设备，这个结论会一直留在文档里当"已对齐"。
