# 第 21 轮评审（2026-11-01）— 写入面系统性复查

r20 的 P1 有个共同模式：**"能写进去"和"写进去之后系统还能跑"是两件事**。
本轮把这条当成一个检查项，逐个过了一遍写入口。

## 1. 复查表

|---|---|---|
| `POST /setup` | 哈希失败 / 已有 admin | 已覆盖（r1、r4） |
| `POST /auth/register` | 保留名、口令强度 | 已覆盖（r3） |

## 2. F-050（P1）一个非法 CIDR 能让租户"永久收不到配置"

`handleCreateNetwork` 此前**只校验 display_name**。可以把
`virtual_cidr` 写成空、`"not-a-cidr"`、`"fd00::/64"` 或 `"10.0.0.0/32"` 全部存进库；
之后 `Compile` 在 `addressSpace` 处返回错误 → `ReconcileUser` 报错 →
`ReconcileAll` 直接返回 → **该租户这一轮一个推送都没有**，只有一行日志。

**修复**：`validateNetworkIntent` 在创建与修改两条路径上校验：

- CIDR 必须存在、必须是 IPv4、前缀在 /8..~/30；
- `PublicServer`：给了 `public_server_url` 就必须是带 scheme + host:port 的合法 URL；
- `Manual` / `Gateway`：必须有 `peer_urls` 或 `public_server_url`，且逐个校验；
- 未知组网方式直接 400。

另在 `Compile` 里加了**子网包含性兜底**：即使库里有历史脏数据，也会得到一条明确的
"member X address Y is outside the network subnet Z"，而不是推一份不可达的配置出去。

## 3. F-051（P2）越界地址会被原样推送

成员 `virtual_ipv4` 此前不做任何校验。写 `10.99.99.99` 进一个 `10.30.0.0/29` 的网络，
编译照收，设备拿到一个对端不可达的地址——故障现象是"能连上但互 ping 不通"，极难定位。

**修复**：`validateMemberAddress`（IPv4 格式 + 子网包含），编译期再加一道包含性检查。

## 4. F-052（P2）重名网络 500 + 泄露约束名

创建同名网络返回
`500 bal: create network: constraint failed: UNIQUE constraint failed: networks.user_id, networks.network_name (2067)`
——既是错误的语义（这是客户端问题），又把表名/列名/约束名交出去（与 r6 的 F-019 同类）。
现在映射为 `409 network_exists`，其余错误统一 `"cannot create network"`。

## 5. 回归与证据

- 冒烟仍端到端通过（建网 → 加成员 → 改名 → 收到两版配置）。
