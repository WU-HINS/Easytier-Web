# 第 234 轮评审（2026-11-01）— 一个 P1：ACL 构建器写出的策略编译不过

本轮本来只想给 ACL 统计补个真机验证。结果在查 "为什么成员一直是 pending" 时，
从 members 接口里看到一行：

    compile_error: central: unknown acl selector type "cidr"

## 1. 这是我上一轮引入的 P1

ACL 构建器写选择器用 any / cidr，而编译只认 all / member / group / subnet（compile.go 的 selectorCIDRs）。
后果不只是"策略没生效"：**整条网络编译失败**，成员永远 pending，界面上没有任何提示——
用户会以为是自己没点保存。

## 2. 修复

- acl-model 改用编译器词表：any → all，cidr → subnet；
- parsePolicy 里做旧值迁移，打开页签再保存即自愈；
- 修完实测：compile_error 消失、instance_id 与 virtual_ipv4 分配、成员 running 从 false 变 true。

## 3. 为什么上一轮没发现

上一轮我断言的是"保存后 JSON 里有没有 deny-ssh / tcp / 10.0.0.0/8"——
**我验证了存进去的是我以为的东西，没验证服务端能不能用它。**
存对了但编译不了，等于没做。

## 4. ACL 统计现在到哪一步

重启 daemon 后调用 acl-stats 返回：

    rpc: remote error: ExecuteError: Instance not found

这条错误是**好消息**：说明服务键、方法索引、请求编码都对，请求确实到了设备的 AclManageRpc，
只是设备上没有那个 instance（同 F-283 的 tun 限制）。要拿到非空计数，得有台真跑起实例的机器。
