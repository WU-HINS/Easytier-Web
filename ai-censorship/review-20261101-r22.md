# 第 22 轮评审（2026-11-01）— 前后端契约

本轮换到最后一个没系统检查过的接缝：**前端调用的路由，后端真的有吗？**

## 1. 新工具：check-contract.mjs

从 `internal/httpapi/*.go` 抽出所有 `HandleFunc("METHOD /path")`，从
`client/src/**/*.ts(x)` 抽出所有 `request<T>('...')` 调用（含
`'/networks/' + id` 这种拼接形式），规范化后逐条比对。

**验证器自身也验证过**：注入一条 `PUT /networks/abc/members`（后端无此路由）→ 脚本输出
"1 client call(s) without a server route" 并 exit 1；删除后恢复 0。

## 2. 立刻发现的问题：F-053（P1）浏览器里无法把设备加进网络

前端的 API 层只有 18 个调用，能建网络、能看成员数，**但没有任何"加成员/删成员/删网络"的入口**。
也就是说：网络功能在 UI 上是**半成品**——建得出来，用不起来。

本轮补了一个成员管理面板（`network-members.tsx`）：

- 列出成员（hostname / 虚拟 IP / device_id / 在线状态 / 临时凭据标记）；
- 从用户自己的设备里挑一台加入（已加入的自动排除）；
- 逐个移除、整网删除（带确认）；
- 编译失败时把 `compile_error` 直接显示出来，而不是静默空列表。

实现细节：只用了既有 UI 原语与 token，配色/尺寸全部走 CSS 变量，所以
`check-design-tokens` 与 `check-contrast` 仍然全绿。
