# 第 142 轮评审（2026-11-01）— 把"从 0 部署"这条路上最后两条 OPEN 收掉

F-229 与 F-230 都属部署面：一条说"备份链路从没被演练过"，一条说"带参数的 DSN 会静默丢掉 pragma"。

## 1. F-230：合并 pragma，而不是放弃默认值

原来的写法是二选一：

    if strings.HasPrefix(dsn, "file:") || strings.Contains(dsn, "?") {
        return dsn, nil        // 带着参数的 DSN 一个 pragma 都不加
    }
    return dsn + "?_pragma=foreign_keys(1)&_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)", nil

于是"照文档在 DSN 里加一个 _pragma=busy_timeout(9000)"的代价是**同时丢掉 WAL 与外键**，而且没有任何日志。
现在逐个 pragma 检查、只补缺的那些。

四种 DSN 都有用例（纯路径 / file: / 带 cache=shared / 已带 busy_timeout），探针恢复旧写法后立刻报：

    /tmp/et.db?cache=shared lost "foreign_keys(1)": /tmp/et.db?cache=shared

## 2. F-229：给"开备份的冷启动"补一条门禁

整个仓库里所有脚本都写着 EASYTIER_DB_BACKUP=0——包括那个号称"一键自检"的 smoke。
于是"首次启动、改 schema 之前先写快照"这条路径，只在单元测试里跑过，而单元测试用的是必定可写的 TempDir。

新增 scripts/check-backup-cold-start.sh（门禁第 23 项）：

| 条件 | 值 |
|---|---|
| DSN | file:<临时目录>/et.db?_pragma=busy_timeout(5000) |
| EASYTIER_DB_BACKUP | 1（**不关**） |
| 备份目录 | 多级不存在的路径 |

断言三件事：进程能起来、目录被创建、**在改 schema 之前留下了快照文件**。

探针（把 DSN 归一化去掉，即 r140 那个 bug）：

    the daemon did not come up with snapshots enabled
    dsm: sqlite backup: open file:/tmp/.../et.db?_pragma=busy_timeout(5000): no such file or directory
    no snapshot was written before the first schema change

这条脚本一次守两件事：r140 的 URI 回归，以及"备份是否真的运行过"。

## 3. 仍未验证的边界

镜像层面（distroless nonroot + 根属主命名卷）在这个环境里没有 docker，**无法实机验证**。
它继续留在 root.md 的"待办与已知边界"里，而不是被这条新用例"顺带证明"。

## 4. 台账

230 项：**220 FIXED / 7 ACCEPTED / 3 MONITOR / 0 OPEN**。

OPEN 清零。3 条 MONITOR 都是需要外部条件才能推进的（docker 实机、多副本、上游语义）。

## 5. 判断

这两条的价值不在修复本身，而在**它们能被守住**：
一条有了四种 DSN 的用例，另一条变成了门禁里的第 23 项，并且探针能证明它会红。
"从 0 部署"这条路，现在有一处是**真的每次都跑**的了。
