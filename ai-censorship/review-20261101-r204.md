# 第 204 轮评审（2026-11-01）— 把"能跑一次"打磨成"每次都能跑"

上一轮四版本真机全通，但那是**手工**跑的。这一轮把它变成可重复的检查，
过程中发现检查脚本自己有 3 个缺陷——每一个都会把"通过"误报成"失败"，或者反过来。

## 1. 三个探针缺陷（F-275）

| 缺陷 | 症状 | 修法 |
|---|---|---|
| python 单行写在双引号里 | 内层 json 键的双引号提前结束字符串，探测恒空，2.4.0/2.5.0 被误判"从未上报" | 改用单引号 |
| 设备 id 只读一次 | 老版本重连后换 id，白名单并的是新 id | 每轮重读 |
| 看到成员就 grep 推送日志 | 推送日志在调用返回后才写，"并网成功但没推"被误判失败 | 改成轮询 30 秒 |

## 2. 稳定性

矩阵连跑两轮：**8/8 全绿**（2.4.0 / 2.5.0 / 2.6.4 / 2.7.0 各两轮）。

## 3. 接入门店

gate.sh 新增第 26 项 real clients（按需）：

    EASYTIER_REAL_CLIENTS=1 ET_CLIENTS="2.4.0:/a 2.7.0:/b" ./scripts/gate.sh

带这一项跑整门禁：**26 项全 PASS**（cited tests 仍按需跳过）。
root.md 与 docs/REVIEW-TEAM.md 的表格同步加到 26 项——顺带踩到一次文档校验规则
（SKIP 行里的 printf 用双引号会被当成步骤名），已改回与相邻行一致的单引号。

## 4. 判断

这一轮没有新功能，价值全在**可信度**：一个会随机红的检查，比没有检查更糟。
顺便记一笔：三次踩坑（JS 模板吃换行、双引号套双引号、grep 与写入的时序）
都属于"我写下的东西与它看起来的不一样"，这也是这个项目里反复出现的同一类错误。
