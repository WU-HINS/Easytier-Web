# 第 209 轮评审（2026-11-01）— ws 的两格：不是路径，是响应

为了补上 2.4.0 / 2.5.0 的 ws，我写了个最小 WebSocket 探针（自己实现 101 握手 + 帧解析 + 解掩码），
把两个版本的首帧都抓下来了。

| | 2.4.0 | 2.6.4 |
|---|---|---|
| 握手路径 | GET / | GET /@up/root-owner |
| 首帧 | 二进制，201 字节 | 二进制，86 字节 |
| 头 | 16 字节 peer 头 | 同 |
| 体 | 185 字节 RpcPacket | 70 字节 RpcPacket |
| 方法 | **Heartbeat（1）** | GetFeature（2） |

结论修正：路径不是问题（我们已经在 / 上接受升级），帧格式也不是问题（两者结构一致）。
**问题是响应**——2.4.0 直接发心跳，我们回的心跳响应它不接受，随即 1006 断开。

这也解释了为什么 tcp 能用而 ws 不能：同样的响应在 tcp 上它接受，在 ws 上不接受，
差别很可能在消息边界或附加字段上，下一轮对着 HeartbeatResponse 的字段逐项核对。
