# 第 65 轮评审（2026-11-01）— 从没被连过的那个端口

r53 补了"额外 TCP 监听"的验证。同一个家族里还有一个：**`--config-server-ws`**（独立 WebSocket 控制面）。
它有实现（`wire.ListenWS`）、有文档、在 `gate.sh` 里被扫过"参数存在"——但**从来没有任何东西连过它**。

## 1. F-121（P2）零覆盖的监听器

控制面有两条路：

| 入口 | 覆盖 |
|---|---|
| `:22020` TCP（长度前缀帧） | 冒烟全程在用 |
| `/api/v1/@up/<user>` WS（挂在面板端口） | r13 起有用例 |
| **`--config-server-ws`（独立 WS 端口）** | **无** |

它坏掉的表现会是：管理员按文档打开这个参数，设备连不上，日志里什么都看不出来。

## 2. 补法：让假设备会走 WS

`cmd/smokedevice` 之前只会 `wire.DialTCP`。加一个 `--transport tcp|ws`：

```go
case "ws":
    url := endpoint
    if !strings.HasPrefix(url, "ws://") { url = "ws://" + url }
    if !strings.Contains(url[len("ws://"):], "/") { url += "/" }
    tunnel, err = wire.DialWS(ctx, url, nil)
```

冒烟新增一段：

```
== standalone ws listener ==
ws listener started            ws://127.0.0.1:18761
member renamed for ws          204
ws device config               1 revision(s) received
```

## 3. 第一次跑失败，但暴露了一个正确行为

第一版**没有**改成员名，设备连上后 **45 秒收不到任何配置**。原因不是 WS 有问题，而是：

> 这台机器（同一个 machine_id）之前已经通过 TCP 拿到过最新修订，库里记着"它是最新的"。
> 于是对账器认为没有变化，不下发。

这是**正确**的行为（不做无意义推送，r37 修的就是"每 5 秒重复下发"）。所以测试里先改一次成员名制造新修订，
再让设备接入——这样既验证了 WS 通道，也顺带确认了"修订未变则不推"。

**记录下来的理由**：测试写错时，先怀疑自己的前提，而不是先怀疑被测代码。
