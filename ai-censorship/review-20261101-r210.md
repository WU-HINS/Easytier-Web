# 第 210 轮评审（2026-11-01）— ws 的两格：是 URL 约定，不是协议

上一轮抓帧已经排除了路径和帧格式，剩下"响应"这条线。这一轮换个角度对了一遍 URL，直接命中。

## 1. 证据

2.4.0 的心跳体里，token 字段是三个字节：

    1a 03 40 75 70     ->  "@up"

而 2.6.4 的是十个字节 "root-owner"。我们给的地址是 ws://host:port/@up/root-owner：

| 版本 | 取哪一段 | 得到的用户名 |
|---|---|---|
| 2.4.0 / 2.5.0 | 第一段 | @up（查无此人） |
| 2.6.4 起 | 最后一段 | root-owner |

所以 2.4/2.5 不是"连不上"，是**带着错误的用户名连上了**，被服务端拒掉后 1006 断开。

## 2. 修法

把控制面地址改成单段路径 ws://host:port/<用户名>：两种解析都得到正确用户名。
实测 2.4.0 / 2.5.0 / 2.6.4 / 2.7.0 全部 PASS。

## 4. 判断

这一轮的教训与 udp 那次是同一个：**我按自己拟定的约定去校验别人**。
udp 那次是把 padding 当哨兵，这次是把 "路径必须叫 @up" 当约定。两次都是先有抓包、后有真相。
