# 第 232 轮评审（2026-11-01）— 语言切换：先做管道，再谈覆盖率

上一轮我把语言切换记为"没做"，理由是文案模块被约 20 个组件直接 import。这一轮把它做成了真的。

## 1. 设计

- copy/locale.tsx：LocaleProvider + useCopy()/useLocale()；
- en-US 表**深合并**到 zh-CN 之上——没翻的键回落到中文，界面不会出现 key 名；
- 选择写入 localStorage，并同步 document.documentElement.lang；
- 外壳与概览改为 useCopy()，其余页面暂不接入。

## 2. 浏览器实测

| 断言 | 结果 |
|---|---|
| 切到 English 后导航变化 | 通过（Overview/Devices/Networks/Blocked devices/Password） |
| 概览标题变化 | 通过（Overview） |
| html lang | 通过（en-US） |
| 刷新后保持 | 通过 |
| 切回中文 | 通过（概览） |
| console error | 0 |

## 3. 一个被检查逼出来的正确写法

check-ui 禁止组件里出现中文字面量。en 表里的 languageZh 是"中文"这个词本身，写进去就违规。
我一开始想给检查加白名单，最后改成从 zh 表取值——**规则是对的，不该为了省事去放宽它**。

## 4. 覆盖范围（诚实）

英文已覆盖：品牌、导航、外壳、通用按钮、概览、登录标题。
其余页面（设备/网络/账户/管理）仍是中文，回落到 zh 表。要全覆盖就是把 useCopy 接到每个组件，工作量机械但明确。
