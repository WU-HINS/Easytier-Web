# 第 138 轮评审（2026-11-01）— 最后一条 OPEN：守卫要证明自己没在撒谎

团队轮留下的 7 条 OPEN，这是最后一条 F-219。它有三块：审计只认退出码、check-docs 只认步骤名、
citations 检查根本没挂进门禁。三块一起补。

## 1. 审计要能说出"为什么红"

原来只要检查器非零退出就算 OK。问题是**崩溃**也非零：
本轮我自己的探针就撞过三次（编译不过、nil panic、readdir 崩），每次都差点被当成"红证"。

现在多一层判定：输出必须非空，且不含 `ERR_MODULE_NOT_FOUND / SyntaxError / ReferenceError / TypeError / panic:`。
不满足就报 `WRONGFUL`。

探针（把 contrast 检查器的加载改成引用不存在的模块）：

    WRONGFUL design contrast (checker crashed instead of reporting)

## 2. check-docs 要比较命令，不只是名字

原来只比对 `run "名字"` 里的引号内容，把任何一个步骤换成 `true` 都能让三方全绿。
现在会解析整行：命令若是 shell no-op（`true/false/:/echo/exit/...`）直接失败，
命令里引用的脚本不存在也失败。

探针：

    gate step "client bundle" runs a shell no-op (true); it can never fail

写这条规则时我犯了个蠢错：正则被模板字符串吃掉了反斜杠，变成 `/^s*runs+.../`，
一条都匹配不上——**新加的守卫自己在空转**。第一次探针没红，我才发现。
改成字符类 `[ 	]` 之后才真的生效。

## 3. citations 以 opt-in 方式挂进门禁

它要重跑全部 140+ 个被引用用例，约三分钟。挂成每轮必跑会让门禁翻倍，不挂又回到"守卫从不执行"。
折中方案是显式化：

| 条件 | 行为 |
|---|---|
| 设了 `EASYTIER_FULL_GATE=1` | 跑 `cited tests` 这一步 |
| 没设 | 打印一行 `SKIP (set EASYTIER_FULL_GATE=1 to run ./scripts/check-citations.sh)`，并计入 summary |

不设时**看得见**它没跑，而不是悄悄消失。

## 4. 台账

221 项：211 FIXED / 7 ACCEPTED / 3 MONITOR / **0 OPEN**。

团队轮给出的 7 条 OPEN，四轮收完。

## 5. 判断

这一轮修的全部是"检查器自己"：它会不会撒谎、会不会空转、会不会没人执行。
F-219 这条 OPEN 是我从团队轮里留下来的最后一块硬骨头，因为它没有"某个函数写错了"那么具体——
它问的是：**你凭什么相信这些绿灯**。
