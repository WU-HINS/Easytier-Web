# 第 159 轮评审（2026-11-01）— 把"没做过长跑"从借口变成数字

docs/DEEP-CHECKS 里挂着一行"有状态长跑：未做"。这一轮把它做掉。

## 1. 长跑的东西其实一直存在

TestSoakDeviceChurn 早就在那里，默认 15 轮——足够跑门禁，不足够叫"长跑"。
它接受 EASYTIER_SOAK_ROUNDS 覆盖轮数，但**没有人用它跑过一次大的**。

这正是这个项目反复出现的形态：能力在，触发条件没人拨。

## 2. 跑了什么

| 方言 | 轮数 | 结果 | 耗时 |
|---|---|---|---|
| SQLite | 1000 | 通过 | 51.8s |
| PostgreSQL | 1000 | 通过 | 39.6s |

不变量依旧是那三条：配置收敛（不重复下发）、无编译错误、无累积。

顺带加了 scripts/soak.sh，参数化轮数，默认 1000：

    ./scripts/soak.sh          # 1000 轮，SQLite
    ./scripts/soak.sh 5000     # 5000 轮
    EASYTIER_E2E_PG=... ./scripts/soak.sh

## 3. 记进深检台账

DEEP-CHECKS 增加一行（r159），写清时间、命令、结论——
下次不必记得"跑过没有"，看表即可。

## 4. 台账

248 项：240 FIXED / 8 ACCEPTED / 0 MONITOR / 0 OPEN。本轮没有新缺陷，属于覆盖补齐。

## 5. 判断

"没做过长跑"和"做过了，1000 轮，两个方言，51.8 秒"是两句完全不同的话。
第二句还能再问"那 10000 轮呢"——但至少它不是一句借口了。

这一轮的产出是**把一句模糊的欠账换成一条可复现的命令和一个数字**。

## 6. 补记：这一轮我把 smoke 弄坏过一次（F-249）

给 UDP 步加"等 ws 会话确实下线"的前置判断时，我用了一次**全文件替换**：
凡是形如"轮询 members 接口"的行都换成了"等成员下线"的断言。
结果命中的是**很早的一行**——"等设备注册完成"的等待循环。

它的条件在那一刻永远为假，于是设备注册的等待变成空转 12 秒，
后面期待两条配置的设备一条都没收到：

    configs received
    FAIL: the member override never reached the device

这是本项目第三次出现"按模式替换命中了更早的同形代码"（r135、r136，以及这一轮）。
三次都在**我自己写的脚本里**，三次都被门禁抓住。

修法：把那行按原样放回（轮询 machines 接口直到出现该 machine），
再跑：configs received 两条、udp device config 一条，smoke 全绿。

记这一笔是因为它说明一件事：**门禁的价值不在于它跑过多少次，
而在于它在我改坏东西的那一次仍然会红。**
