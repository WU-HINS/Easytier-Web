# 第 51 轮评审（2026-11-01）— 构建产物本身

前端此前的检查全是**源码级**：token 纪律、对比度、状态分支、契约一致性。
但用户拿到的是 **`client/dist`**——那里出问题，源码再干净也是白屏。

## 1. F-104（P2）三类白屏事故没有任何守卫

| 事故 | 后果 | 现在能被发现吗 |
|---|---|---|
| `index.html` 指向已删的哈希资源 | 页面加载 JS 404 → 白屏 | 不能 |
| bundle 被 tree-shake 成空（路由没被引用） | 白屏 | 不能 |
| 依赖里出现 `eval` / `new Function` | 被**我们自己的 CSP** 拦截 → 白屏 | 不能 |

第三类尤其讽刺：`script-src 'self'` 是我们 r2 加的安全头，它同时意味着
**任何使用 `eval` 的依赖都会在运行期被自己禁掉**。源码看不见这个问题，只有产物里才有。

## 2. `scripts/check-bundle.mjs` 四条断言

1. `index.html` 里所有 `src=` / `href=`（相对路径）都必须在 `dist` 中存在；
2. `id="root"` 与 `/boot.js` 必须存在；
3. JS 总大小不得低于 50 kB（低于此值说明路由被摇没了）；
4. bundle 内不得出现 `eval(` 与 `new Function(`。

**验证器自身验证过**：把 JS 资源挪走 → 报"references a missing file"+"no javascript bundle"；
往 bundle 尾部注入 `eval("1+1")` → 报"uses eval(), which our CSP blocks"。

当前实测：3 个资源引用、285 kB JS、CSP 干净。
