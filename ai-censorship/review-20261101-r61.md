# 第 61 轮评审（2026-11-01）— 极端碰撞：阻止与心跳抢同一个会话

r56 加了"阻止设备时立即断开会话"。那段代码是唯一的写路径吗？不是——**心跳会并发地注册会话**。
两个动作抢同一张表，单线程用例看不出来。

## 1. F-117（P2）关会话 vs 注册会话

`DisconnectDevice` 与心跳里的 `m.register(session)` 都会动 `m.sessions`。
最坏的交错是：

1. 心跳完成认证，准备注册；
2. 管理员阻止设备，`DisconnectDevice` 遍历现有会话（此时还看不到这个新的）；
3. 心跳把会话注册进去 —— **设备仍然在线**。

这是典型的 check-then-act 窗口。要证明它不存在（或存在），只能让两件事真的并发跑。

## 2. TestBlockDuringHeartbeatStorm

```
4 条隧道 × 每 20ms 一次心跳
150ms 后：DELETE /machines/{id}?block=true
断言：会话数归零、IsBlocked 为真、没有 DATA RACE
```

`-race` 下连跑 3 次稳定通过（13.8s）。全套 `gate.sh` 在 `EASYTIER_RACE=1` 下 14 项全绿。

## 3. 这个用例真正验证的是什么

不是"没有数据竞争"——那是 `-race` 的功劳。它验证的是**语义上的终态**：
一旦阻止完成，无论有多少条隧道正在心跳，最终一个都不剩。

如果第 2 步的窗口真的存在，这个断言会周期性失败（心跳每 20ms 一次，窗口被踩中的概率不低）。
它没有失败，说明查询会话表与认证在同一把锁的保护下——这点值得记下来，因为它是隐含的。

## 4. 判断：什么时候该写并发用例

这套系统里"并发抢同一张表"的地方不多，但要挑对：

| 位置 | 有并发用例吗 |
|---|---|
| 网络配置修订（CAS） | 有（r22） |
| 配额裁剪 vs 上报 | 有（r19） |
| 分片合并（RPC） | 有（r25） |
| 阻止 vs 心跳注册 | **本轮补上** |
| 删除成员 vs 对账 | 有（r38） |
