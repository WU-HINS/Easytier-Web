## 1. 我自己上一轮的修复有洞（F-250）

r151 我把编辑器改成"与打开时快照比较"，解决了后台刷新造成的假脏值。
但快照**成功后不推进**，于是同一次挂载内的第二次保存会把上次已存的字段重发，
正好把 F-228/F-242 声称消灭的覆盖问题请了回来；清空输入还被判成"无改动"而静默丢弃，
界面却显示"成员已更新"。

修法三处：成功后推进基线；空 patch 不发请求且禁用保存按钮；输入变化复位 saved。

## 2. UDP 客户端的两处移植漏项（F-251、F-252）

| 缺陷 | 对照 |
|---|---|
| udpClientTunnel 有 writeMu 没有 readMu，而 Recv 每次都改共享 socket 的读超时 | tcp 与 ws 两个实现都有 readMu |
| 客户端把畸形数据报当致命错误，Mux.Run 对 Recv 错误直接 return | 服务端同一位置写着"丢弃，不致命" |

一条脏包就能打死整条控制通道，而服务端认为这类包应当被忽略。

## 3. soak.sh 是"假长跑"（F-253）

测试内层 ctx 固定 3 分钟，与 EASYTIER_SOAK_ROUNDS 无关：
宣传 5000 轮，实际 3 分钟就被截断，还会被脚本报成"收敛失败"。
而且轮数没有下界，soak.sh 0 空跑通过。

修法：ctx 随轮数放大（每轮 2s，下限 3 分钟），测试与脚本都拒绝小于 1（实测 0 与 abc 均被拒）。

上轮我宣布"长跑跑过了 1000 轮"时，那句话在这个预算下仍然成立（51.8s 远小于 180s），
但机制是错的：它能跑完靠的是运气，不是设计。
