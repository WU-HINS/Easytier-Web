# 第 211 轮评审（2026-11-01）— 换成无 tun 模式：实例终于跑起来了

沙箱没有 CAP_NET_ADMIN，之前每一轮真机都停在 tun 创建失败。这一轮改用 EasyTier 的无 tun 模式验证。

## 1. 做法

不用 CLI 开关，而是走控制台自己的通道：网络高级设置里下发 no_tun=true，
两个官方 2.7.0 客户端连上来后自然拿到这份配置。

## 2. 结果（真机）

| 观察项 | 结果 |
|---|---|
| tun 错误 | **0**（此前每次必现 Operation not permitted） |
| 虚拟 IP | node-a 10.161.0.1、node-b 10.161.0.2 |
| 接口状态 | running=true、online=true |
| 成员级 listener_urls 覆盖 | 生效：客户端日志 new listener added，ss 显示 11021/11022 已绑定 |

这同时验证了两件事：网络级 no_tun 真的下发到了客户端；节点级覆盖在真实客户端上生效（此前只有单元测试）。

## 3. 没做到的

两台实例之间**没有建立对等**：easytier-cli peer 各自只看到自己。
peer_urls 在编译期确实写进了 PeerUrls，PATCH 也返回 200，但实例没连上——怀疑客户端只在实例创建时应用 peers。
另发现 API 形状不一致：创建时 peer_urls 要放顶层，放 settings 下会被静默忽略（我第一版就是这么写的）。
已记为 F-282 OPEN。

## 4. 判断

这一轮把"配置能下发"推进到"实例能真正跑起来"，但**组网互通仍然没有证据**。
不把 no-tun 成功当成组网成功——这两件事之间还差一次对等连接。
