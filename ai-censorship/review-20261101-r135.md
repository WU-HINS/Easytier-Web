# 第 135 轮评审（2026-11-01）— 收 OPEN 单，以及一次"探针打错人"

团队轮留下的 7 条 OPEN，这轮先收两条最影响"从 0 部署"和"越权语义"的。

## 1. F-214（P2）备份目录不存在 → 首次启动必挂

仓库自带三份配置（Dockerfile、docker-compose.yml、.env.example）都把
`EASYTIER_DB_BACKUP_DIR` 指向不存在的目录，而代码里没有任何 `MkdirAll`。
首次启动要建表 → 走备份分支 → 打开文件失败 → 进程退出 1。README 把这条当作"宁可起不来"的正当行为，
但没写"目录必须预先存在"，而三份配置自己就没满足它。

修法：写快照前 `MkdirAll(dir, 0o700)`。测试用三级不存在的目录。

探针（去掉 MkdirAll）复现的正是用户会看到的那行：

    backup: dsm: sqlite backup: open .../nested/deeper/backups/et-backup-....db: no such file or directory

顺带发现旧用例 `TestBackupRunsBeforeSchemaChange` 是靠"目录不存在"来制造失败的——
修复后它自己红了。改成用一个普通文件挡路，断言本意（快照失败必须中止对齐）保持不变。

## 2. F-217（P2）对别人的 id 返回 204

三处一起改：

| 端点 | 原行为 | 现在 |
|---|---|---|
| `DELETE /api/v1/networks/{id}` | 0 行也 204 | 404 |
| `DELETE /api/v1/machines/blocked/{id}` | 0 行也 204 | 404 |
| `DELETE /api/v1/machines/{id}?block=true` | **先写 block 再校验归属** | 先校验，404 且不留行 |

探针（把 0 行判断改成 `if false && ...`）：`foreign delete = 204 , want 404`；
探针（移除归属预检）：`the rejected request left 1 blocked row(s)`。

## 3. 这轮最该记住的一件事：我的探针打错了函数

第一次给 F-217 做探针，我按"把 `if affected == 0 { return ErrNotFound }` 从文件里删掉"来写。
连跑三次，测试都**通过**，我一度以为测试写错了。

真相：bal 里好几个函数结尾是同一个形状，`str.replace(..., 1)` 改的是**最先出现的那一个**，
不是 `DeleteNetwork`。探针改了个无关函数，当然什么都证明不了。

改用"先定位函数名、再在函数体内替换"之后，第一次运行就红：

    foreign delete = 204 , want 404

这和 r118（探针编译不过）、r127（探针 nil panic）、r133（探针崩在 readdir）是同一族：
**探针自己也会骗人**。判据只有一个——探针失败的原因必须是你想验证的那个原因。

## 6. 门禁里另一起误伤：审计继承了数据库地址（F-221）

这轮门禁先失败了一次，两条原因：

| 现象 | 真实原因 |
|---|---|
| `postgres steps FAIL (database not reachable)` | PostgreSQL 实例又停了（r133 加的预检正确报出了原因） |
| `BROKEN single admin index / quota inside the transaction / duplicate username` | 审计的 Go 变异继承了门禁导出的 `EASYTIER_TEST_PG_DSN`，数据库一停，三条"必须可红"的用例在 restore 之后仍然失败 |

第二条尤其坏：它把**基础设施故障**记成了**守卫退化**。修法是在审计的 `go test` 前加
`env -u EASYTIER_TEST_PG_DSN -u EASYTIER_HTTPAPI_PG`——这些变异本来就不需要数据库（SQLite 足够）。

验证方式是最直接的那种：故意给一个不可达的 59999 DSN 跑审计，16/16 仍然全部可红。

顺带把实例拉起来了（数据目录 `/tmp/pgtest/data`，属主 `pgtest`，残留 pid 要先删）。
