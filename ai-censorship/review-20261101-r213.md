# 第 213 轮评审（2026-11-01）— 两台受管实例第一次真正连上了

上一轮把问题收窄到"推送的 peer_urls 没被采用"。这一轮读 upstream 源码找到了原因，并且修好了。

## 1. 根因（一行代码）

easytier-core/src/config/api_input.rs 里：

    NetworkingMethod::Standalone => {}
    NetworkingMethod::Manual => { peers = parse_peer_urls(&self.peer_urls)? }

**Standalone 分支是空的：peer_urls 被整段忽略。** 我们的编译器把"带 peer 的独立网络"编成 Standalone，
于是 peers 永远到不了客户端。

修法：Standalone 且 peer_urls 非空时，编译为 Manual。

## 2. 真机结果（公开节点）

    | 10.173.0.2/29 | pb | relay(2) | 767.00 | 0.0% |
    | 10.173.0.1/29 | pa | relay(2) | 767.00 | 0.0% |

两台受管实例互相可见，双方都挂在 PublicServer 上、经中继通信。**这是本项目第一次在控制台驱动下真正组网。**

## 3. 没做到的：数据面（F-283）

port-forward 到对端虚拟 IP 超时；用成员级 proxy_cidrs 暴露本机 127.0.0.2/32 后再转发仍超时。
对照直连 127.0.0.2:9001 返回 overlay-ok，说明服务与转发规则本身没问题，缺的是"proxy 是否热生效"。

## 4. 判断

上一轮我说"没把节点通了当成组网通了"——这一轮补上了"对等"这一半，但仍然没把"数据通过"当成已达成。
