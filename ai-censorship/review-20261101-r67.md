# 第 67 轮评审（2026-11-01）— 关掉挂了 53 轮的有状态 fuzz

F-036 是 r14 登记的：现有的模糊测试只把**单个包**喂给全新的 Mux，跨包时序从来没人试过。
一直挂着是因为"需要状态机 harness"——其实只要一个固定种子的伪随机序列就够了。

## 1. F-036（P2）从单包到序列

`TestStatefulPacketSequencesStayBounded`：同一个 Mux 连收 400 个随机包，覆盖

| 维度 | 取值 |
|---|---|
| 事务 id | 0..3（故意重复，制造交错） |
| 请求/响应 | 2:1（给陌生 tid 发响应） |
| total_pieces | 0..4（含 0 和 1 的退化情形） |
| piece_idx | 0..6（**故意越界**） |
| 中途 sweep | 每 8 个包一次 |

断言两条：合并缓冲不超过上限（64），以及 sweep 之后归零。

## 2. 一个"防止自己骗自己"的探针

随机段有个隐患：**它可能根本没走到装配路径**（比如所有包都被当成完整消息处理了），
那样这个用例永远绿，却没测到任何东西。

所以先来一个确定性前置：发一个 `total_pieces=4, piece_idx=0` 的孤片，等 merger 出现（≤3s），
**没出现就失败**。这条过了，才说明后面的随机段确实在碰装配状态机。

## 3. 初版是 flaky 的，被 `-count=20` 抓了出来

第一版在每次发送后立刻采样 `MergerCount()` 来判断"有没有形成 merger"——但发送是异步的，
采样经常错过。`-count=20` 跑出约 1/10 的失败：

```
stateful_test.go:52: no partial assembly ever formed; the sequence never exercised the merger path
```

也就是说：**探针本身是好的，只是触发方式不可靠**。改成"确定性前置 + 随机主体"后，
`internal/rpc` 连跑 20 次（222s）和 `-race -count=3` 全部通过。
