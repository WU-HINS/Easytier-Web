# 第 20 轮评审（2026-11-01）— 补齐 2.7.0 的编辑面

r19 补齐了网络/成员的改名与移除。本轮继续对照 2.7.0 路由表，补齐 ACL 策略、
成员级覆盖配置、以及接入凭据三组端点。补的过程中又发现两个真问题。

## 1. 新增端点

| 端点 | 说明 |
|---|---|
| `GET /networks/{id}/acl-policy` | 读取策略原文 |
| `PUT /networks/{id}/acl-policy` | 写入前用 `central.ParsePolicy` 校验 |

## 2. F-048（P1）非法 ACL 策略会静默停掉整个租户的下发

`compilePlan` 会解析 `network.ACLPolicy` 与 `member.OverrideConfig`。解析失败时
`ReconcileUser` 返回错误，`ReconcileAll` 直接返回，于是**该租户这一轮一个推送都没发**，
而且只有一行 `reconcile failed` 日志——设备只是"永远收不到配置"。

**修复**：写入即校验。`PATCH /networks/{id}`、`PUT /acl-policy`、`PUT /members/{device}/config`
四条写入路径全部先解析，非法直接 400，库里不会再出现让编译失败的数据。

**回归**：`TestMemberAndNetworkEditing` 断言 PATCH 带非法 acl_policy 返回 400；
`TestACLMemberConfigAndCredentials` 断言 PUT 非法策略/非法覆盖都返回 400，合法值可回读。

## 3. F-049（P2）吊销不存在的凭据返回 204

`RevokeCredential` 只把 `Exec` 的错误往上抛，没看影响行数，于是删一个不存在的 id 也"成功"。
删除类接口报告成功但什么都没发生，是最容易让人误判的状态。现在检查影响行数，0 行 → `ErrNotFound` → 404。

## 4. F-047（P2）凭据列表未校验归属

`GET /networks/{id}/credentials` 直接按 (user, network) 查，跨租户得到 **200 空列表**。
没有数据泄露（查询本身带租户过滤），但语义与其它端点不一致，也会把"网络 id 打错"这类问题藏起来。
现在先校验网络归属，跨租户 404。

**越权矩阵**：本轮的测试对 5 个新端点逐个用另一个租户的会话请求，全部要求 404。

## 5. 凭据的安全约定

- secret 用 `auth.RandomToken(24)` 生成（约 192 bit），**只在创建响应里出现一次**，列表接口永不返回；
- 吊销按 (user, network, credential) 三元组过滤，跨租户吊销表现为 404。

## 6. 仍未覆盖

- ACL 策略**生效性**没有端到端验证（只验证了"写入合法"与"编译不报错"）。
  真正验证需要：设置一条拒绝规则 → 两个设备互 ping → 断言被拒。需要真实的 easytier 数据面，当前环境没有。
- 前端尚未提供 ACL / 凭据 / 覆盖配置的界面（后端已就绪）。
