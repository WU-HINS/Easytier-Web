# 第 248 轮评审（2026-11-01）— 升级与回滚终于有证据了

生产评审里有一句我很在意："本会话没有验证过升级/回滚流程（只验证了冷启动）。"
冷启动只证明"空库能跑"，完全不说明"有数据的库换版本会怎样"。

## 1. 怎么做的

`scripts/upgrade-drill.sh`：

1. 用 `git worktree` 检出 40 个提交前的版本并编译（不是 stash，也不是假装的"旧版"）；
2. 旧二进制在空库上建管理员 + 一个网络；
3. 新二进制在同一个库上启动：断言管理员能登录、网络还在（前向迁移）；
4. 再用旧二进制启动：记录它能否读迁移后的库。

## 2. 结果（两个库都跑）

    sqlite     forward migration keeps the admin and the network
    sqlite     rollback: the old binary still reads the migrated database
    postgres   forward migration keeps the admin and the network
    postgres   rollback: the old binary still reads the migrated database

也就是说：**这个项目目前是可回滚的**——不是"仅前向"。这条以前没人验证过。

## 3. 过程里的两个修正

- 第一次跑 PostgreSQL 直接 "old binary did not start"：因为我连的库不存在（没 createdb）。
  顺手改了脚本：**启动失败要打印该二进制的日志尾**，否则"没起来"三个字对排障毫无帮助。
- 上一轮我差点把"postgres 失败"当成代码问题——它其实是环境准备缺失。
