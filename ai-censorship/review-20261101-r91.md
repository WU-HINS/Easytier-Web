# 第 91 轮评审（2026-11-01）— 前端的两条安全规则，只有代码没有证据

到这一轮，后端的敏感规则大多有了断言。前端的**安全规则**还没有——它们只存在于 TypeScript 里，靠人读。

## 1. F-155（P2）G7 的两条规则

| 规则 | 位置 | 有验证吗 |
|---|---|---|
| OIDC 回调地址由**浏览器**生成（管理员把它抄进 IdP） | `oidcCallbackURL()` | 没有 |
| 非 https（且非环回）源**不启用**绑定 | `isSecureOrigin()` | 没有 |

这两条与后端 `validateCallbackURL` 是配对设计的：前端生成、后端只接受同源 https。
任何一边悄悄改掉，另一边都会变得没有意义。

## 2. 先做一步小重构

这些函数原本住在 `http.ts` 里，而那个文件有 `class ApiError extends Error { constructor(readonly status: number, ...) }`——
参数属性是 Node 的 strip-types 不支持、transform-types 才支持的语法。为了让门禁能直接 import，把三个纯函数抽到无依赖的 `client/src/lib/origin.ts`，
`http.ts` 只做 re-export。

顺带的好处：**安全和 URL 相关的逻辑与网络层分开了**，前者可以被单独审查。

## 3. 门禁第 18 项

`scripts/check-client-origin.mjs`：用 stub 的 `window.location` 跑五种来源——

| 来源 | isSecureOrigin | 回调地址 |
|---|---|---|
| https://console.example | true | https://console.example/api/v1/auth/oidc/callback |
| http://localhost:11211 | true | 同源 |
| http://127.0.0.1:11211 | true | 同源 |
| http://[::1]:11211 | true | 同源 |
| http://console.example | **false** | 仍是同源（但界面不会给绑定入口） |

每种来源同时断言 `absolute()` 生成的地址，防止前缀被改到别处。

## 7. 判断

前端此前能"被机器检查"的东西都是**样式与契约**（token、对比度、路由、可访问名）。
这一轮第一次把**前端的行为规则**也放进了门禁——用的还是同一条思路：让它可被 import，就能被断言。
