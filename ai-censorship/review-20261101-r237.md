# 第 237 轮评审（2026-11-01）— 把网络配置还原成人类能读的样子

用户两次提到：「原本的网络配置很贴合人类」。我据此去查了原版到底怎么做的——
答案是 **TOML**：config-generator 把配置渲染成可以直接粘进配置文件的形式，还能反向解析回来。

## 1. 我们其实一直有引擎，只是没接线

- internal/configtext：Document{instance_name, hostname, ipv4, mtu, no_tun, listeners, peer[], proxy_network[]}；
- /generate-config 与 /parse-config 都在；
- **client/src 里一次都没调用过**（契约检查早就把这两条路由列在"没有客户端调用"里）。

所以这一轮不是写引擎，是**把已经做好的东西接到人眼前**。

## 2. 做了什么

| 层 | 改动 |
|---|---|
| 后端 | GET /networks/{id}/members/{device}/toml，用编译结果渲染（不是拼面板状态） |
| 前端 | 成员 override 区新增「生效配置（TOML）」：可读、可编辑、可复制、可保存 |
| 保存路径 | TOML → parse-config → 映射成 Overrides（snake_case 子集）→ PUT override |

## 3. 两次踩坑，都值得记

**坑一：保存直接 400。** 我把 parse-config 的输出原样当 override 提交，服务端回 `unknown field "virtualIpv4"`——
override 只接受一份**子集**且是 snake_case（mtu / no_tun / listener_urls / proxy_cidrs…）。
于是加了 toml-overrides.ts 做映射，并处理 proxyNetworks 对象→CIDR 字符串的转换。

**坑二：我原来的断言太浅。** 第一版只断言"面板里有 instance_name"，mtu 改没改进去根本没查。
加上"改成 1400 → 保存 → 刷新仍为 1400"之后才真正验证了闭环。

## 4. 实际渲染出来的东西

    instance_name = "edge-hk-01"
    hostname = "edge-hk-01"
    ipv4 = "10.180.0.1"
    mtu = 1380
    no_tun = true
    network_name = "生产网"
    network_secret = "…"

    [[peer]]
      uri = "tcp://v4v6.usvps.server.ddns.hinswu.top:21010"

这就是"贴合人类"的样子：字段名是 EasyTier 配置文件的字段名，不是内部枚举。
