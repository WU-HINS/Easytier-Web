# 第 244 轮评审（2026-11-01）— proxy-rpc：把"能代理一切"改成"只能读"

F-009 从第一轮起就是 ACCEPTED，理由写的是"仅限自有设备"。这一轮把理由拿掉了——因为更好的做法是根本不给它写的能力。

## 1. methodindex 里到底有什么

翻了一遍方法表，能通过 proxy 转发的包括：

- RunNetworkInstance / DeleteNetworkInstance / RetainNetworkInstance（启停设备上的实例）
- GenerateCredential / RevokeCredential / UpsertCredential（发凭据）
- SetLoggerConfig（改日志级别）
- UpdateDnsRecord（改 DNS 记录）
- SyncRouteInfo（灌路由）

这些在控制台里**都有自己的专用端点**，proxy 完全不需要它们。所以白名单只保留只读方法。

## 2. 实现与验证

| 项 | 内容 |
|---|---|
| 白名单 | proxy_allowlist.go：10 个服务、21 个只读方法 |
| 拒绝 | 不在表里 → 403，消息直接说不在白名单上 |
| 测试 1 | 11 条写方法/未知服务必须被拒 |
| 测试 2 | 6 条读方法必须放行 |
| 测试 3 | 白名单每一项都必须在 methodindex 中存在——否则就是写了永远转发不了的条目 |

真机实测（起一个空控制台打接口）：

    403  api.manage.WebClientService/RunNetworkInstance
    403  api.instance.CredentialManageRpc/GenerateCredential
    403  api.logger.LoggerRpc/SetLoggerConfig
    404  api.instance.PeerManageRpc/ListPeer     ← 过了闸门，只是没有设备

## 3. 一点判断

"只能访问自己的设备"确实是当前的真实边界（会话按 userID 查）。但把写能力留在一条通用通道上，
意味着以后任何一次鉴权改动都会放大成"能远程启停设备"。白名单是把这种放大可能性直接删掉，成本只有 21 行表。
