# 第 162 轮评审（2026-11-01）— 上一轮说"测不了"，其实是我测错了对象

上一轮我宣布 F-252（客户端把脏包当致命错误）写不出可红用例，理由是 connected UDP socket
按四元组过滤，第三方数据报进不来。**那个理由只对"用 socket 测"成立。**

## 1. 把规则从 socket 里拿出来

脏包该怎么处理，是一条纯规则：空帧、仅帧头、超长、低于 peer 头、声称长度超过实收，五种都是噪声。
它不需要 socket 就能验证——只要把这段逻辑从 Recv 里抽出来：

    parseDatagramFrame(buffer, read) (*Packet, error)  // 噪声返回 errSkipDatagram

Recv 遇到哨兵就继续读，其它错误照常返回。

## 2. 用例与探针

TestParseDatagramFrameSkipsNoise 覆盖五种噪声 + 一条合法帧；
探针把哨兵换成普通错误后立即红：

    empty: err = wire: bad frame, want errSkipDatagram

## 3. 判断

上一轮的结论是"这条修复没有守卫"，这一轮的结论是"**我上一轮测的是传输通道，不是规则**"。

同一件事，换个粒度就能测。以后遇到"测不了"，先问一句：
我要验证的是"这条规则"，还是"这条规则经过这条通道之后的行为"？
前者几乎总能测，后者常常不能。
