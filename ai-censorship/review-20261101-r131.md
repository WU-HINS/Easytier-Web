# 第 131 轮评审（2026-11-01）— 同一个比例，四种写法

回到 R-A（前端美观）。这次不查"有没有用 token"，而是查**同一个设计决定被写了几遍**。

## 1. F-204（P2）黄金比例被写了四份

| 位置 | 写法 |
|---|---|
| `styles/globals.css` 的 `.phi-split` | `61.8% 38.2%` |
| networks-page | `lg:grid-cols-[1fr_0.618fr]` |
| settings-page（admin） | `lg:grid-cols-[1fr_0.618fr]` |
| appearance-page | `lg:grid-cols-[1fr_0.618fr]` |

两种单位、四个位置，而且**没有一处读 `--phi`**。改 token 时布局纹丝不动。

修法：三个页面改用 `.phi-split`（保留各自的 gap 类），内联比例为 0；
再加一条规则——组件里出现 `0.618fr` / `61.8%` / `38.2%` 即失败。

## 2. F-205（P1）检查器有一条"整行豁免"

写完规则后，探针居然没触发。查原因是检查器里的这段：

    if (line.includes("var(--")) continue;

**同一行只要出现任意 CSS 变量，该行所有字面量都不再检查。**
所以 `className="text-[#ff0000] gap-[var(--x)]"` 一直是合法的——颜色写死也看不出来。

把豁免收窄成"只有命中片段本身在 `var(` 上下文中才跳过"，立刻抓到一个真实违规：

    ui/badge.tsx:16  px literal  2px

改为 `py-[calc(var(--u-3)/4)]`——仍然是 2px，但来自阶梯。

## 3. 一条元教训

这轮的两个问题都出在**检查器自己**：

| 现象 | 类型 |
|---|---|
| 比例写了四份却没人发现 | 规则缺失 |
| 一行有 var 就整行豁免 | 规则过宽 |

而"规则过宽"只有在写完新规则、做探针、发现探针**不触发**时才会浮出来。
如果我只看到"检查通过"就收工，这条 P1 会继续潜伏。
