# 第 242 轮评审（2026-11-01）— 把界面断言塞进 CI，顺便抓出三个真问题

生产评审的第 2 条阻塞是「ui-tour 不在 CI 里」。这一轮把它接进去。

## 1. 不能只是加一个 job

脚本原来的前提是「库里有网络、有设备」——那是我的演示环境，不是 CI 的起点。CI 拿到的是空库。
所以先让脚本对数据自适应：空库时经页面上下文创建「CI 冒烟网」并在结束时删除；
设备表列、搜索空态、成员相关面板按「有数据 / 无数据」分别断言。

## 2. 空库一跑，立刻抓到三个真问题

| 现象 | 真正的原因 |
|---|---|
| 建网 401 | context.request 与页面不是同一份 cookie 存储；改用 page.evaluate 里的 fetch |
| 凭据表断言失败 | 无凭据时表格不渲染，断言「表头含 ACL 组」必然失败；改成先签发再断言 |
| 空态文案断言失败 | 我写的是「还没有设备」，实际 copy 是「尚无设备」——断言用的是我的记忆，不是代码 |

第三条最值得记：这条断言在本地一直是绿的，因为它从没被执行到（本地有设备，走的是另一个分支）。

## 3. 结果

- ci.yml 新增 ui-tour job：client 构建 → 装 chromium → 起控制台（setup token 初始化）→ 跑断言 → 上传截图 artifact；
- 空库本地实跑：23 checks, 0 failed。

比本地 28 条少 5 条，是因为设备与成员相关的那几条在空库里改为断言「空态」，不是被删掉。
