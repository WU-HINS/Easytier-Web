# 第 34 轮评审（2026-11-01）— 未填字段的默认值，逐个核对

r33 的收尾问题是"我们没填的 NetworkConfig 字段，默认值与上游等价吗"。本轮读 `gen_config()` 逐个核对，
并且抓到一个**与上游相反的假设**。

## 1. F-079（P1）PublicServer 不给 URL，实例根本起不来

上游 `gen_config()` 里：

```rust
NetworkingMethod::PublicServer => {
    let peers = parse_peers(&self.peers)?;
    if peers.is_empty() {
        let public_server_url = self.public_server_url.clone().unwrap_or_default();
        cfg.set_peers(vec![PeerConfig { uri: public_server_url.parse()? , ... }]);
    }
}
```

空字符串 `parse()` 直接失败 → **整份配置生成失败 → 实例起不来**。
核心没有"内置默认服务器"这回事。

而 r21 我当时的判断是"PublicServer 不给 URL 也可以，easytier 会用默认服务器"——**这个判断是错的**，
并且当时没有验证，直接写进了"允许"分支。结果：任何用 API 建一个不带 URL 的 PublicServer 网络的用户，
都会得到一个"创建成功、永远起不来"的网络。

**修复**（两道）：

- 写入侧：`validateNetworkIntent` 对 PublicServer 强制要求 `public_server_url`，返回 400 并点名字段；
- 编译侧：`validateCompiledConfig` 再查一次（挡住历史脏数据 + 其他入口）。

回归 `TestPublicServerRequiresURL`（API 400 且文案含字段名）与
`TestCompileRejectsPublicServerWithoutURL`（编译拒绝；补上 URL 后正常）。

## 2. F-080（P2）金样对空格风格敏感 —— 第二次踩

跑门禁时金样又红了，原因还是 `instance_id: "x"` vs `instance_id:  "x"`。
r32 我处理方式是"重新生成 + 归一化 diff 人工确认"，但**根因没除**。

本轮把归一化做进渲染函数：冒号后的连续空格统一成一个，金样只记录语义。
重建后与旧金样的语义 diff 为**空**，连跑 3 次稳定。

（上一轮我把这条记成 ACCEPTED，现在看是错的——重复出现的问题不该被"接受"，该被消除。）
