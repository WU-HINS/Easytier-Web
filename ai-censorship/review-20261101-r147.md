# 第 147 轮评审（2026-11-01）— 给新传输加脏流量与竞态

上一轮修完"断线后无法重连"，这一轮继续压这套新写的 UDP 代码：
不是找新功能，而是问它**在真实网络里会遇到、而回环测试里遇不到的东西**。

## 1. 加了一条风暴用例

TestUDPSurvivesGarbageAndManyPeers：12 个并发对端，每个先发三种畸形数据报
（零长度、声称 4GB 的巨帧、长度与载荷不符的截断帧），再发一帧合法数据。

断言两件事：

1. 12 个对端**全部**能被 accept 到（脏流量不得饿死正常对端）；
2. 每帧合法载荷都能被收到。

## 2. 竞态检测

新增代码是并发的（读取协程、回收协程、Accept、每个对端的 Send/Recv），
所以这一轮把竞态检测也跑了一遍：

| 包 | 结果 |
|---|---|
| internal/wire | 0 DATA RACE |
| internal/session | 0 DATA RACE |
| internal/central | 0 DATA RACE |

记入 docs/DEEP-CHECKS.md，并说明门禁也可以带 RACE 跑（EASYTIER_RACE=1）。

## 3. 这一轮的结果是"没发现问题"

需要说清楚：本轮净产出是**覆盖**，不是修复。风暴用例第一次跑就过，
竞态检测也没有报警。这有两种可能——代码确实没有这类问题，或者用例还不够狠。

我倾向后者仍需观察：真实脏流量的形态（乱序、重复、IP 分片、NAT 超时）比这里复杂。
所以这条用例的作用是**留下一根桩**：以后再改这个文件，至少不会静默退化。

## 5. 判断

"没有发现问题"的一轮也是结果，前提是**说清楚你找过什么**。
这轮找的是：畸形帧、并发对端、数据竞争。没找的是：乱序/重复语义、跨 NAT 行为，
以及 UDP 上层 RPC 的重复执行——最后一条是真正的空白：UDP 会重复投递，
而我没验证过 rpc.Mux 是否按事务 id 去重。
