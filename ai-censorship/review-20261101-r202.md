# 第 202 轮评审（2026-11-01）— 下发被拒：排除了六种键组合和一个 peer 假设

目标：让 2.4.0+ 真机全部接入。这一轮在 2.7.0 上把"下发被拒"缩小到一个具体线索。

## 1. 做了三个实验，都被证伪

| 实验 | 结果 |
|---|---|
| 6 种服务键组合（proto × service）自动重试 | 全部 InvalidService，错误里显示最后一种 api_manage.WebClientService |
| 出站请求按客户端自己的 peer id 寻址 | 仍 InvalidService |
| 只改 proto_name（上一轮） | 仍 InvalidService |

结论：不是"名字拼错"，是客户端**根本没有注册这个服务**。

## 2. 留下的线索

客户端日志里出现过：

    GetFeature RPC failed; using legacy tunnel

我们没实现 GetFeature（方法 2），客户端因此降级到"老式隧道"模式。
在这个模式下它很可能不注册 WebClientService，而期待控制台用另一条链路下发配置。
**下一轮的第一件事：读 easytier-core 的 legacy 分支，看老模式到底怎么下发。**

- 白名单自动并网成功；
- 这两条在 2.7.0 上稳定复现。
