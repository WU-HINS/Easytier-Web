# 第 215 轮评审（2026-11-01）— 给"对等"上锁，并把"做不到"写进门店

上一轮拿到了两台实例互见的真机证据，但那条证据只活在我的一次手动运行里。这一轮把它固化。

## 1. 探针（先证明守卫是真的）

把 compile.go 里的 Standalone→Manual 映射改回去，再跑 overlay smoke：

    == step 1: both instances run and are members ==
      ok: two members running without a tun device
    == step 2: the two instances find each other ==
    overlay smoke: FAIL: node-a never saw node-b in its peer table

恢复后通过。**这条守卫会在修复被回退时变红**，不是摆设。

## 2. 接进门禁

gate.sh 第 27 项（按需）：

    EASYTIER_OVERLAY_SMOKE=1 ET_BIN=/path/easytier-core ./scripts/gate.sh

语义分三档：0 → PASS；3 → **SKIP（对等 OK，数据面需要 tun）**；其他 → FAIL。
整门禁实跑结果：

    == overlay smoke                SKIP (peering ok; payload needs a tun device)
    result: PASS

## 3. 踩到的坑

第一次接入时门禁直接以退出码 3 结束——因为 gate.sh 开头是 set -e，而我把脚本当普通命令执行，
非零立即中止。改成 if ...; then status=0; else status=0; fi 才对。
这类"把子命令失败当成门禁失败"的问题，正是 set -e 与"允许特定退出码"混用时最容易踩的一处。

## 4. 判断

目标里的"数据面"这一格仍然空着，但它现在有名字、有退出码、有一行门店输出，
任何人把它跑绿都能立刻替换掉这个 SKIP。
