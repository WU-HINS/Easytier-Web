# 第 207 轮评审（2026-11-01）— udp 大部分通了，但 2.6.4 退回去了

这一轮先把 udp 做通（16 字节会话头 + Sack），然后跑完整矩阵，发现结果并不齐整：

| 版本 | tcp | ws | udp |
|---|---|---|---|
| 2.4.0 | PASS | FAIL | PASS |
| 2.5.0 | PASS | FAIL | PASS |
| 2.6.4 | PASS | PASS | **FAIL** |
| 2.7.0 | PASS | PASS | PASS |

## 1. udp 的实现（已确认有效）

- 8 字节会话头 + 8 字节 magic，msg_type=1 是 Syn；
- 服务端必须回 Sack（同 conn_id、同 magic），否则客户端每 3 秒重发；
- Data 的 body 就是 ZCPacket。

回归用例 TestEasyTierUDPSessionHandshake，探针去掉 Sack 后立即失败。

## 2. 2.6.4 的 udp 为什么不算通过

连续 3 次 FAIL。控制台日志显示会话建立后 15 秒被 idle 关闭，客户端只有
"GetFeature rpc failed, fallback to legacy tunnel"，之后**没有心跳到达**。
同一命令一小时前曾经 PASS，所以我不打算把它记成"通过"。

已经排除两种猜测（都做了实验）：

1. Syn 到达即接受会话 → 改回只按 Data 接受，仍 FAIL；
2. conn_id 在重新握手时刷新 → 回退，仍 FAIL。

## 3. 判断

这轮的净产出是"udp 三种版本可用 + 一整套可复现的矩阵"，以及一条明确的**未解决**记录。
把 2.6.4 写成绿的会省事，但那正是这个项目一直在清理的那种假绿。
